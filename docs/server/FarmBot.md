## `test-client/BotConsole.cs` — บอทคอนโซล (`--console`)

พิมพ์คำสั่งแล้วบอทแปลงเป็น packet ให้ (แนวเดียวกับ OpenKore) — เก็บ world state จาก packet ที่ server ส่งมา
จึงตอบได้ว่าตอนนี้มีใคร/อะไรอยู่ตรงไหน โดยไม่ต้องเปิดตัวเกม

```bash
cd test-client
dotnet run --no-build -- --console 127.0.0.1 8191 bot-1          # พิมพ์คำสั่งเอง
dotnet run --no-build -- --console --cmd "look; farm 20; status" # สั่งรวดเดียวแล้วออก
dotnet run --no-build -- --console --script scripts/demo.txt     # อ่านจากไฟล์
```

| คำสั่ง | ทำอะไร |
|---|---|
| `status` / `inv` / `look` | สถานะตัวเอง · ของในกระเป๋า · สิ่งที่อยู่รอบตัว (เรียงตามระยะ) |
| `move <tx> <ty>` / `goto <id\|near\|player>` | เดินไปพิกัด / เดินไปหา entity |
| `touch [tx ty]` / `collect [gen]` / `farm [วินาที]` | เก็บของ (farm = วนเองจนครบเวลา) |
| `target` / `attack [id] [action]` / `kill [id] [วินาที]` | ต่อสู้ (kill = ตีซ้ำจนตายหรือหมดเวลา) |
| `revive` | ฟื้นหลังตาย |
| `craft <recipe> [slot=itemId ...]` / `equip <itemId> <slot>` | คราฟต์ / สวมของ |
| `chat <ข้อความ>` / `cheat <คำสั่ง>` | พูด / ส่ง packet Cheat (`add axe`, `spawn`, `die`, `rest` ...) |
| `control <ชื่อ> <คำสั่ง>` | คุมตัวละครของผู้เล่นคนอื่น — ดู [RemoteControl.md](RemoteControl.md) |
| `chunk` / `actions` / `dump` / `wait` / `quit` | ขอ chunk ใหม่ · ดูท่าที่มี · โชว์ packet ดิบ · รอ · ออก |

**โครงสร้าง:** เธรดเดียวจัดการ packet ทั้งหมด (loop `Process()`), เธรดอ่าน stdin แยกแล้วส่งคำสั่งเข้า queue
handler จึงไม่ต้องกังวลเรื่อง race

## `test-client/FarmBot.cs` — บอทฟาร์มไว้เทส (`--bot`)

**หน้าที่:** ต่อเข้า server แล้วเก็บของ/เดินเองไม่ต้องมีคนกด ใช้ทดสอบเกมเพลย์ยาว ๆ โดยไม่ต้องเปิดตัวเกม

ทำไมต้องมี: ตัวเกมจริงมีบทสนทนา NPC / prologue คั่นอยู่ ซึ่ง **server สั่งปิดไม่ได้**
(`GameManager.cs:172` `IsPrologueMode = IsSceneName("Prologue")` — client ตัดสินจากซีน Unity)
บอทไม่มี UI จึงข้ามเรื่องพวกนั้นไปได้ทั้งหมด

## วิธีรัน

```bash
cd test-client
dotnet run --no-build -- --bot [host] [port เกม] [นาที] [ชื่อ] [port gateway]

# ตัวอย่าง: ฟาร์ม 5 นาทีในชื่อ farmbot-1
dotnet run --no-build -- --bot 127.0.0.1 8191 5 farmbot-1
```

- ไม่ใส่ port gateway = **พอร์ตเกม − 1** (8190)
- ชื่อที่ใส่ถูกใช้เป็นทั้ง entity id และชื่อที่โชว์ ⇒ ชื่อเดิม = ผู้เล่นคนเดิม (มีไฟล์เซฟของตัวเอง)

## ลำดับการทำงาน

1. **ขอ session token จาก gateway** (`SessionClient.Fetch`) — GP-12 บังคับ ไม่มี token = โดนปฏิเสธตั้งแต่ `Auth`
2. `GetClock` → `Auth` → `Ready` → `SetChunk` รอบจุดเกิด
3. วนลูปจนครบเวลา:
   - มีจุดที่แตะค้างอยู่ → ส่ง `Collect` ต่อจนกว่าจะหมด
   - ไม่มี → เลือกของธรรมชาติ**ที่ใกล้ที่สุดที่รู้จัก** เดินไปยืนบนจุดนั้น แล้ว `Touch`
   - ข้ามเขต chunk เมื่อไหร่ก็ `SetChunk` ใหม่เพื่อรู้จักของเพิ่ม

## รู้ตำแหน่งของธรรมชาติได้ยังไง (สำคัญ หลัง GP-09)

server ส่ง garden มากับ packet `Chunk` — record ละ 6 ไบต์: `x:u16, y:u16, entityType:u16`
(ตรงกับ `Durango.Terrain.NaturalInfo` ฝั่ง client) บอทแกะเก็บใส่ `naturals` แล้วใช้เลือกเป้าหมาย

ก่อนหน้านี้บอทสุ่ม tile แล้วเดาชนิดของเอา — ใช้ได้เพราะ server เชื่อ client
พอ GP-09 บังคับว่า tile ต้องมีของจริงและต้องอยู่ในระยะเอื้อม วิธีเดิมจะโดนปฏิเสธทุกครั้ง

`Abort` จาก server = จำ tile นั้นไว้ใน `badTiles` แล้วไม่กลับไปอีก (ของหมด / ไกลเกิน / สตามินาไม่พอ)

## สรุปผลตอนจบ

พิมพ์: จำนวน touch / collect / ของที่ได้จริง / abort / เดิน / ของในกระเป๋า + รายการของที่เก็บได้แยกตามชนิด

ตัวเลขที่ควรเห็นเมื่อทุกอย่างปกติ: **abort = 0** และ "ได้ของจริง" ควรใกล้เคียง "สั่งเก็บ"
(ต่างกัน 1 ได้ เพราะรอบสุดท้ายอาจยังรอ `Collected` อยู่ตอนหมดเวลา)

## เคยจับบั๊กอะไรได้บ้าง

- **กระเป๋าล้น**: เก็บได้ 52 ชิ้นทั้งที่ `MaxSize = 50` → แก้แล้ว เทสซ้ำได้ 50 พอดี + abort 13 ครั้ง
  ตรงกับ log `[inventory] กระเป๋าเต็ม` 13 บรรทัด
- ใช้เป็นตัวยืนยันว่า GP-09 ไม่ได้ทำให้การเก็บของปกติพัง (ฟาร์มได้ 10 ชิ้นใน 24 วินาที abort 0)
- **ทิ้งของ/กินของไม่มี handler** (โซกเทส 30 นาที 15 ส.ค.): bot เก็บจนเต็ม 50 ช่องใน ~2 นาที
  แล้วหลังจากนั้นวนแตะ-โดนปฏิเสธไปจนจบ เพราะ `DumpItems`/`UseItem` ไม่มีใครรับ → เพิ่ม handler แล้ว
- **บอทวาร์ปจนโดน M-2 ปฏิเสธทุกก้าว**: bot เดิมกระโดดไปยืนบนเป้าหมายทันที
  ทำให้โซกเทสรอบแรกวัดอะไรไม่ได้ → ตอนนี้เดินทีละก้าวที่ 450 หน่วย/วินาที

## ของคู่กัน: `--gp-check`

`test-client/GpCheck.cs` — ยิง packet แบบ **client โกง** แล้วเช็คว่า server ปฏิเสธจริงไหม

```bash
dotnet run --no-build -- --gp-check [host] [port เกม] [port gateway]
```

ครอบคลุม **36 ข้อ**: GP-08 (คราฟต์ลม) · GP-09 (โกงพิกัด) · GP-12 (Auth ปลอม) · GP-14 (โกงเลเวล)
· ต่อสู้ (ท่ามั่ว/ระยะเกิน/ตายแล้วยังตี) · รอบ D (จองที่/สร้าง/กล่อง/ช่องอุปกรณ์/สกิล)
· ทิ้งของ/กินของ — และปิดท้ายด้วยการทำ "ของที่ควรทำได้" เพื่อยืนยันว่าไม่ได้ห้ามมั่ว
(คราฟต์ด้วยของจริงสำเร็จ · ทิ้งของจริงแล้วของหายจริง)
คืน exit code 1 ถ้ามีข้อไหนตก (เอาไปใส่สคริปต์เทสอัตโนมัติได้)

## `--multi-check` — เทสหลายคนพร้อมกัน

`test-client/MultiCheck.cs` — ต่อ 3 client พร้อมกันด้วยชื่อ `multi-1..3` (ต้องอยู่ใน whitelist)

```bash
dotnet run --no-build -- --multi-check [host] [port เกม] [port gateway]
```

เทส 9 ข้อ: เข้าพร้อมกันได้ · ไม่มีใครโดนเตะ · เห็นกันและกัน · แตะจุดเดียวกันได้ ·
เห็นจำนวนที่เหลือชุดเดียวกัน (GP-03) · **แย่งเก็บของจุดเดียวกันแล้วของไม่ถูกปั๊ม** ·
มีคนเก็บได้จริง · คนที่แย่งไม่ทันโดนปฏิเสธ · ทุกคนยังต่ออยู่หลังเทส

ข้อสำคัญคือข้อ "ไม่ถูกปั๊ม": ทั้งสามคนยิง `Collect` จุดเดียวกันคนละ 5 ครั้งบนของที่มี 3 หน่วย
ถ้า server จองแบบไม่อะตอมมิกจะได้รวมเกิน 3 ชิ้น

⚠️ ทิ้งไฟล์เซฟผู้เล่นชื่อ `gp-check-*` ไว้ใน `server/saves/players/` ลบทิ้งได้เลย
