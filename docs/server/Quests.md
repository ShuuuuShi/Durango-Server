# ระบบเควส

โค้ด: `ServerCore/QuestData.cs` (ตารางนิยาม) · `ServerCore/ServerPlayer.Quests.cs` (ตัวระบบ)
เทส: `dotnet run -- --quest-check` (20 ข้อ) · ดูสถานะในเกม: `cheat quests`

---

## 1. ข้อมูลเกมให้อะไรมาบ้าง (และไม่ให้อะไร)

ตาราง `quests_for_client` มีเควส **1,386 อัน** แต่มีแค่ 8 ฟิลด์:

```json
"story_enter_safehouse": {
  "category": "story", "quest_type": 2, "order": 100,
  "display_on_hud": false, "auto_finish": true,
  "icon": "...",
  "subject":     {"신입사원": null},
  "description": {"앙코라를 탈출해야 합니다. 뗏목을 만드세요.": null}
}
```

**ไม่มีเงื่อนไข ไม่มีเป้าหมาย ไม่มีรางวัล ไม่มีจำนวนที่ต้องทำ สักฟิลด์เดียว**
ตรรกะทั้งหมดอยู่ฝั่ง server ของ NEXON ซึ่งไม่ได้ติดมากับ client
(โรคเดียวกับ `exp_amount` ของสัตว์ที่เป็น 0 ทุกตัว และจุดเกิดสัตว์ที่ไม่มีในไฟล์ terrain)

⇒ **เราใช้ id ของจริง แล้วเขียนเงื่อนไข/รางวัลเอง**

ที่ได้จากการใช้ id จริง: **ชื่อ · คำอธิบาย · ไอคอน · การจัดกลุ่มบน HUD** ของแท้จากตัวเกม
และถ้าวันหลังเปิดแค็ตตาล็อกไทยได้ **ข้อความจะกลายเป็นไทยเองทันที** โดยไม่ต้องแก้อะไร
เพราะ `subject`/`description` เป็นชนิด `Gettext` ที่วิ่งผ่านระบบแปล
(`GettextConverter.ParseObject` → `T.ParseMsgIdAndGetString`) — ดู `docs/client/TUNING.md` §2.1

## 2. โปรโตคอล

`QuestToDo` มีแค่ `{Id, Progress, GoalCount, Finished, EndAt, Reward}` — **server นับทั้งหมด client แค่วาด**

| ทิศทาง | packet | ใช้ตอน |
|---|---|---|
| client → server | `GetQuests {Category}` | เปิดหน้าเควส |
| client → server | `GetQuestState {QuestIds[]}` | ถามสถานะเฉพาะบางอัน |
| client → server | `RequestQuestReward {QuestId}` | กดรับรางวัล |
| server → client | `Quests {Category, Todos[]}` | รายการเควส |
| server → client | `NotifyQuestProceed {QuestId, Progress, GoalCount, Finished}` | ความคืบหน้าขยับ (HUD เด้งตัวเลข) |
| server → client | `QuestStarted {Category, Quests[]}` | มีเควสใหม่โผล่ |
| server → client | `QuestRewardResults {Category, QuestId, Reward}` | รับรางวัลสำเร็จ |

### 💡 ชื่อหมวดมาจาก server

`QuestCategories.Epic.Name` เป็นข้อความที่ **server ส่งไปเอง** ไม่ได้อ่านจากตารางในตัวเกม
⇒ **ใส่ภาษาไทยได้เลยตั้งแต่วันนี้** (ตอนนี้ตั้งเป็น `"เอาชีวิตรอด"`)
ต่างจากชื่อเควสรายอันที่ยังเป็นเกาหลีจนกว่าจะแก้เรื่องแค็ตตาล็อก

### แพที่ใช้

blueprint **`tutorial_boat`** (탈출용 뗏목 = "แพหนีภัย")

| | |
|---|---|
| วัสดุ | ท่อนซุง 4 (tag `pillar_*`) + ก้าน 6 (tag `stem`) |
| เครื่องมือ | ไม่ต้องใช้ |

## 4. ตัวนับ — ไม่ได้เขียนใหม่สักตัว

เกี่ยวกับจุดที่มีอยู่แล้วทั้งหมด (จุดเดียวกับที่เรียก `GainProficiency`):

| ทำอะไร | จุดที่เกี่ยว |
|---|---|
| เก็บของ | `GainExpForGather()` → `Goal.Gather` · `NoteGatheredItem(prototype)` → `Goal.GatherItem` |
| ล่าสัตว์ | `GainExpForKill()` → `Goal.Hunt` |
| แล่ซาก | `GainExpForButchery()` → `Goal.Butcher` |
| คราฟต์ | `GainExpForCraft(meta)` → `Goal.Craft` (+ หมวดสูตร · หมวด cook ยิง `Goal.Cook` ด้วย) |
| สร้าง | `GainExpForBuild(blueprintId)` → `Goal.Build` (+ blueprint id) |
| กินอาหาร | `HandleUseItem` → `Goal.Eat` |
| ขึ้นเลเวล | `CheckLevelQuests()` → `Goal.Level` |

> ⚠️ **เรียกตอน "ทำสำเร็จจริง" เท่านั้น** ไม่ใช่ตอนกดสั่ง — ไม่งั้นยิง packet รัว ๆ ที่ถูกปฏิเสธก็เดินเควสได้
> (กติกาเดียวกับความสึกของเครื่องมือและความชำนาญ)

`Goal.Level` ต่างจากตัวอื่นตรงที่ **วัดจากค่าปัจจุบัน ไม่ใช่นับสะสม** จึงเช็คตอนขึ้นเลเวลและตอนเข้าเกม
(เผื่อเลเวลถึงตั้งแต่ก่อนเปิดระบบเควส)

## 5. กติกาเวลาเพิ่มเควสใหม่

1. **ใช้ id จริงจาก `quests_for_client`** — id ที่ client ไม่รู้จักจะไม่ขึ้นบน HUD (ไม่พัง แต่ไม่โชว์)
2. **`Count` ต้องตรงกับตัวเลขในคำบรรยายเกาหลีของ id นั้น**
3. `Requires` ชี้ไปเควสก่อนหน้าเพื่อทำเป็นสาย · เว้นว่าง = เปิดตั้งแต่แรก
4. ถ้าเควสเจาะจงเป้าหมาย ให้ใส่ `Param` (prototype / หมวดสูตร / blueprint id)
5. เขียน `Thai` ไว้ด้วยเสมอ — ใช้แจ้งผ่าน `Info` ตอนรับ/สำเร็จ **ซึ่งเป็นไทยได้ทันทีวันนี้**

## 6. ผลเทส (`--quest-check` 26/26)

| กลุ่ม | ผล |
|---|---|
| เข้าเกมได้รายการเควส · ขั้นถัดไปยังไม่โผล่ | ✅ |
| ยังไม่ครบแล้วกดรับรางวัล → ไม่ผ่าน | ✅ |
| เก็บของจนครบ → `NotifyQuestProceed` 10 ครั้ง · ขั้นถัดไปโผล่ · ได้ `QuestStarted` | ✅ |
| รับรางวัล → ได้ exp จริง (20→40) · ได้ไอเทมจริง (ก้าน 0→3) | ✅ |
| กดรับซ้ำ → ไม่ผ่าน | ✅ |
| **ต่อแพด้วย packet จริง (`OccupyArtifactSite` → `BuildArtifact`) → เควสปลายสายสำเร็จ 1/1** | ✅ |
| ออกเกมเข้าใหม่ ความคืบหน้ายังอยู่ | ✅ |

## 6.1 ความทนของระบบ (รอบทำให้เสถียร)

| กันอะไร | ทำยังไง |
|---|---|
| **ตารางเควสพิมพ์ผิดแล้วเงียบ** | `QuestData.ValidateAndReport()` ตรวจตอนเปิดเซิร์ฟ — id ซ้ำ · `Requires` ชี้ไปที่ไม่มีจริง · สาย `Requires` วนกลับ · `Count < 1` · ไม่มีข้อความไทย |
| **เด้ง "เควสใหม่" ซ้ำ** | จำรายตัวใน `_questAnnounced` (เดิมใช้เงื่อนไข "ความคืบหน้า = 0" ⇒ เด้งซ้ำทุกครั้งที่เควสอื่นสำเร็จ) |
| **เควสเลเวลสำเร็จแล้วขั้นถัดไปไม่โผล่** | `CheckLevelQuests` เรียก `AnnounceNewQuests` เมื่อมีอะไรสำเร็จ |
| **รางวัลซ้ำ / ให้รางวัลซ้อน** | มาร์คก่อนให้ของ + ธง `_grantingQuestReward` (การให้ exp ทำให้ขึ้นเลเวล → เช็คเควสเลเวล → อาจวิ่งกลับมา) |
| **ให้รางวัลพังกลางทาง** | จับ exception แจ้งผู้เล่น ไม่ให้ล้มทั้ง handler |
| **ตัวเลขในเซฟโตไม่หยุด** | ตัดความคืบหน้าที่เป้าหมายก่อนเก็บ |
| **แก้ตารางแล้วเซฟเก่าเพี้ยน** | ตอนโหลดทิ้ง id ที่ไม่มีในตารางแล้ว (ไม่งั้นถ้าเอา id เดิมไปใช้กับเควสอื่น ผู้เล่นเก่าจะได้ "เสร็จแล้ว" ฟรี) |
| **packet พิลึก** | id ที่ไม่มีจริง/ว่าง/หมวดที่ไม่มี → ตอบ `Abort` ไม่ล่ม (มีเทสครอบ) |
| **ปั๊มเควสด้วยการสร้างซ้ำ** | แก้ที่ระบบก่อสร้าง — ดู `Building-Audit.md` ข้อ 1 |

## 7. ที่ยังไม่ได้ทำ / ข้อควรรู้

- 🔴 **การสร้างสิ่งปลูกสร้างไม่กินวัสดุเลย** — `PutMaterialsIntoArtifact` ตอบ `OK` เฉย ๆ
  ⇒ ต่อแพได้โดยไม่ต้องมีท่อนซุง/ก้านจริง · ขั้น "เก็บท่อนซุง 10 อัน" จึงเป็นตัวสอนอย่างเดียว
  **นี่เป็นช่องโหว่ของระบบก่อสร้าง ไม่ใช่ของระบบเควส** — ควรแก้แยกต่างหาก
- ชื่อ/คำอธิบายเควสในหน้าต่างยังเป็น**เกาหลี** จนกว่าจะเปิดแค็ตตาล็อกไทย
  (ข้อความแจ้งทาง `Info` เป็นไทยแล้ว · ชื่อหมวดเป็นไทยแล้ว)
- ยังไม่มี **เควสประจำวัน** (id `daily_*` มีพร้อมใช้ ~9 อัน แต่ต้องมีระบบรีเซ็ตรายวันก่อน)
- ยังไม่มี **บทสนทนาตอนรับ/ส่งเควส** (`quest_start_messages` / `quest_end_messages` มีในข้อมูล 21/102 อัน)
- `cheat questskip` = ตัวช่วยเทส ทำทุกขั้นให้เสร็จยกเว้นขั้นสุดท้าย (ไม่ให้รางวัล)
