# ระยะการมองเห็น (interest management)

**ส่งเฉพาะสิ่งที่อยู่รอบตัวผู้เล่นแต่ละคน** แทนที่จะส่งทุกอย่างให้ทุกคนในเกาะ

โค้ด: `ServerCore/ServerPlayer.Vision.cs` · `ServerWorld.BroadcastNear/BroadcastToViewers/Announce*`
ค่าตั้ง: `data/config.json` → `World` (hot-reload 5 วิ ไม่ต้อง build)
เทส: `dotnet run -- --vision-check` (12 ข้อ)

---

## 1. ปัญหาเดิม

`ServerWorld.Broadcast` ส่งให้ **ทุกคนในเกาะโดยไม่ดูระยะเลย** และถูกเรียกจาก **47 จุด**
รวมทั้งการเดินของผู้เล่นและการเดินของสัตว์ทุกตัว

| คนออนไลน์ | packet ที่ส่งออกต่อวินาที (เดินคนละ 2 ครั้ง/วิ) |
|---:|---:|
| 3 | ~18 |
| 32 (เพดานเดิม) | ~2,000 |
| 100 | **~20,000** |

โตแบบ **N²** — และ client ทุกเครื่องต้องรับ/วาดคนที่อยู่คนละมุมเกาะซึ่งมองไม่เห็นอยู่ดี
(บนเครื่องเทสที่การ์ดจอเป็น GeForce 210 ยิ่งหนัก — ดู `docs/client/TUNING.md`)

---

## 2. วิธีแก้ — ต้องมี 2 ส่วน ขาดอันใดอันหนึ่งไม่ได้

### ส่วนที่ 1 · กรองตอนส่ง

| เมธอด | ใช้กับ | ระยะที่ใช้ |
|---|---|---|
| `BroadcastToViewers(entityId, msg)` | ข่าว**เกี่ยวกับ entity ตัวหนึ่ง** — เดิน · โดนตี · ตาย · เปลี่ยนชุด · หลอดเลือด | คนที่ "เห็น entity นั้นอยู่" |
| `BroadcastNear(pos, msg)` | เหตุการณ์ที่ผูกกับ**จุดในโลก** ไม่ใช่ entity — ต้นไม้หาย · จุดเก็บของเปลี่ยน | ระยะหาย (ViewExit) |
| `Broadcast(msg)` | **แชทเท่านั้น** (เหลือ 3 จุดในโค้ดทั้งหมด) | ทุกคน |

`BroadcastToViewers` ถูกต้องกว่าการวัดระยะดิบ ๆ เพราะคนที่ยังไม่ได้รับ `Appear` ของ entity นั้น
**ไม่ควรได้รับข่าวของมันเลย** — ไม่งั้น client ได้ `Move` ของ entity ที่ตัวเองไม่รู้จัก

### ส่วนที่ 2 · รอบตรวจว่าใครเข้า/ออกระยะ

`ServerWorld.TickVisibility` → `ServerPlayer.TickVisibility` ทุก `ViewCheckSeconds` (0.4 วิ)

ไล่เทียบ "สิ่งที่อยู่ในโลกตอนนี้" กับ "สิ่งที่คนนี้เห็นอยู่" แล้ว:
- เพิ่งเข้าระยะ → ส่ง `AppearPlayer` / `AppearAnimal` / `AppearArtifact`
- เพิ่งออกนอกระยะ → ส่ง `DisappearEntity`

> ⚠️ **ถ้าทำแค่ส่วนที่ 1 อย่างเดียว คนที่เดินเข้ามาใหม่จะไม่มีวันเห็นใครเลย**
> เพราะเขาได้รับแต่ packet ของสิ่งที่ตัวเองรู้จักอยู่แล้ว ไม่มีอะไรบอกว่า "ตรงนั้นมีคนอยู่"

## 3. ระยะเข้ากับระยะออกตั้งไม่เท่ากันโดยตั้งใจ

```
        เริ่มเห็น (ViewRangeTiles = 24)
              ↓
   ●━━━━━━━━━━┫░░░░░░░░┫
   ตัวเรา              ↑
                หายไป (+ ViewMarginTiles = 8 ⇒ 32)
```

ถ้าใช้ระยะเดียว คนที่ยืนพอดีขอบจะ **โผล่-หาย-โผล่-หาย** ทุกครั้งที่ขยับไม่กี่ก้าว
(ปัญหาคลาสสิกของระบบกรองระยะ) — ช่องว่าง 8 tile ตรงกลางคือตัวกันอาการนั้น

`BroadcastToViewers`/`BroadcastNear` ใช้ **ระยะหาย** ไม่ใช่ระยะเริ่มเห็น เพราะของที่คนหนึ่ง
เห็นอยู่แล้วต้องอัปเดตต่อจนกว่าจะหลุดจริง ๆ ไม่งั้นจะค้างกลางอากาศในช่วง 24-32 tile

---

## 4. ค่าตั้งใน `config.json` → `World`

| ค่า | ค่าเริ่มต้น | ความหมาย |
|---|---:|---|
| `ViewRangeTiles` | 24 | ระยะที่เริ่มเห็นกัน (1 tile = 200 หน่วยโลก) |
| `ViewMarginTiles` | 8 | เลยไปอีกเท่านี้ถึงหาย (⇒ หายที่ 32 tile) |
| `ViewCheckSeconds` | 0.4 | ตรวจเข้า/ออกระยะทุกกี่วินาที |
| `ViewCulling` | true | ปิด = กลับไปส่งให้ทุกคนเหมือนเดิม |

**ทำไม 24/8:** `ChunkSendRange = 2` ⇒ client มี terrain รอบตัว ~40 tile
ระยะเห็น 24 (≈1.5 chunk) จึงกว้างกว่าที่จอแสดงพอสมควร แต่ยังอยู่บนพื้นที่ที่ client โหลดไว้แล้ว
และระยะหาย 32 ยังห่างจากขอบ terrain (40) อยู่ ⇒ ไม่มีทางเห็นคนลอยอยู่บนพื้นที่ยังไม่โหลด

### วิธีจูนตอนเล่นจริง

1. ให้สองคนเดินห่างกันช้า ๆ แล้วดูว่าอีกฝ่ายหายตอนไหน
2. ถ้า**หายทั้งที่ยังเห็นในจอ** → เพิ่ม `ViewRangeTiles`
3. ถ้า**โผล่กะทันหันกลางจอตอนเดินเร็ว** → เพิ่ม `ViewRangeTiles` หรือลด `ViewCheckSeconds`
4. ถ้าเห็น**กระพริบตรงขอบ** → เพิ่ม `ViewMarginTiles`

แก้ไฟล์แล้วมีผลใน 5 วินาที ไม่ต้องปิดเซิร์ฟ

## 5. กติกาสำคัญเวลาแก้โค้ดต่อ

### 5.1 `Appear` ต้องออกทาง `Observe*` เท่านั้น

```csharp
// ❌ ห้าม — รอบตรวจถัดไปจะเห็นว่า id นี้ยังไม่อยู่ในเซ็ต แล้ว "ส่ง Appear ซ้ำอีกที"
_world.BroadcastNear(animal.Position, animal.MakeAppear());

// ✅ ถูก — Observe* จะเช็คเซ็ตให้ก่อน ส่งครั้งเดียวเสมอ
_world.AnnounceAnimal(animal);
```

`ObservePlayer` / `ObserveAnimal` / `ObserveArtifact` เป็น**ทางเข้าเดียว**ของการ "เริ่มเห็น"
ทั้งรอบตรวจและ `Announce*` เรียกผ่านตัวเดียวกัน จึงไม่มีทางส่งซ้ำ

### 5.2 ของถูกลบออกจากโลก → ใช้ `AnnounceGone`

ส่ง `DisappearEntity` ให้ทุกคน (ไม่ดูระยะ) **แล้วล้าง id ออกจากเซ็ตของทุกคนด้วย**
ถ้าไม่ล้าง เซ็ตจะค้างและ `CanSee` จะคืน true ให้ของที่ไม่มีอยู่แล้ว

ส่งให้ทุกคนโดยตั้งใจ — คนที่เคยเห็นแล้วเดินหนีไปอาจยังถือ entity ค้างอยู่ที่ client
packet เล็กและเหตุการณ์ไม่ถี่ จึงไม่คุ้มที่จะไปไล่เช็คว่าใครเคยเห็นบ้าง

### 5.3 แชทห้ามกรอง

`SayInExclusiveChannel` / `SayInConversation` เป็นช่องรวมทั้งเกาะ — ต้องใช้ `Broadcast` ต่อไป
ตอนนี้เหลือ `_world.Broadcast(` ในโค้ดทั้งหมด **3 จุด และเป็นแชททั้งหมด**
ถ้าวันหลังเห็นเลขนี้เพิ่มขึ้น แปลว่ามีคนเผลอเพิ่ม broadcast ที่ควรกรองระยะ

## 7. ที่ยังไม่ได้ทำ

- **`SetChunk` / garden** ยังส่งตามกรอบ chunk เหมือนเดิม (คนละระบบกับตัวนี้ และทำถูกอยู่แล้ว)
- **ยังไม่มี spatial index** — รอบตรวจวนทุก entity ต่อผู้เล่น 1 คน
  ที่ 100 คน × (100 คน + 500 สัตว์ + 4,000 สิ่งปลูกสร้าง) ≈ 460,000 การเทียบระยะทุก 0.4 วิ
  ยังไหวอยู่ (เป็นการคูณ float ล้วน) แต่ถ้าสิ่งปลูกสร้างโตกว่านี้ควรทำ grid ต่อ chunk
- **สิ่งปลูกสร้างไม่เคยขยับ** — ตอนนี้ยังวนเช็คทุกรอบเหมือนของที่เคลื่อนที่ได้
  ถ้าจะปรับให้เร็วขึ้น เช็คเฉพาะตอนผู้เล่นข้ามขอบ chunk ก็พอ
