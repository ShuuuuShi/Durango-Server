# ระบบทำอาหาร (Features.Cooking)

> เปิดแล้วใน beta 1.0 — สูตรหมวด `cook` 152 อัน (+ `cook_season2` อีก 5 ที่ยังปิด)
> ตรวจข้อมูลทั้งระบบด้วย `dotnet run -- --recipe-check` · เทสกับเซิร์ฟจริงด้วย `dotnet run -- --cook-check`

---

## 1. ทำไมของเดิมยังไม่นับว่า "ทำอาหารได้"

ก่อนหน้านี้สูตรทำอาหารอยู่ในลิสต์ 720 สูตรอยู่แล้ว แต่ 3 อย่างทำให้มันไม่มีความหมาย:

| ปัญหา | ผลที่เกิด |
|---|---|
| **server ส่ง `AppearArtifact.Tags = null` เสมอ** | client ใช้ tag ของโต๊ะตัดสินว่าสูตรไหนทำที่นี่ได้ (`Recipe.IsValidWorkbench`) ⇒ ไม่มี tag = **587 จาก 720 สูตรกดไม่ได้เลย** รวมสูตรทำอาหารทุกอัน |
| **ไม่ตรวจโต๊ะ/เครื่องมือฝั่ง server** | ยิง packet ตรงก็ต้มน้ำซุปกลางทุ่งได้โดยไม่มีไฟ ไม่มีหม้อ |
| **ผลลัพธ์เป็น prototype ของ "ชื่อสูตร"** | คราฟต์สูตร `broth` ได้ไอเทม prototype `broth` ซึ่งไม่มีอยู่จริงในเกม (ของจริงคือ `broth_meat` / `broth_vege` ตามวัตถุดิบที่ใส่) |
| **กินอะไรก็ได้ +30 สตามินาเท่ากันหมด** | `IsEdible` เดาจากคำในชื่อ prototype ⇒ ต้มทั้งเย็นได้ผลเท่ากับกัดผลไม้ดิบ |

### ทำไม `WorkbenchTagData.cs` ต้องเขียนเอง

สูตรบอกว่า "ต้องใช้โต๊ะที่ติด tag `cook` ระดับ 40" แต่ **ตารางว่าสิ่งปลูกสร้างไหนติด tag อะไร
ไม่ได้ติดมากับ client** (อยู่ฝั่ง server ของ NEXON) — กรณีเดียวกับ tag เครื่องมือใน `ItemTagData`

ตารางที่เขียนขึ้นอ้างหลักฐาน 3 อย่าง: รายชื่อโต๊ะ 67 อันจาก `performance.workbench` ·
ชื่อเกาหลีใน `blueprints` (모닥불 = กองไฟ · 아궁이 = เตาดิน · 부엌 = ครัว · 가마 = เตาเผา) ·
และระดับที่สูตรจริงเรียกใช้ · `--recipe-check` จะเตือนถ้ามีสูตรที่ไม่มีโต๊ะตัวไหนทำได้เลย

## 3. ไล่ระดับการทำอาหาร

| โต๊ะ | tag | ทำอะไรได้ |
|---|---|---|
| กองไฟ (`bonfire`) | cook 15 | ย่าง/ต้มพื้นฐาน — ผู้เล่นใหม่มี blueprint นี้ตั้งแต่แรก |
| กองไฟใหญ่ (`bonfire_01`) · แคมป์กริล | cook 40 | ต้มน้ำซุป · สูตรระดับกลาง |
| เตาดิน (`furnace_01`) | cook 45 + kiln 35 | ทำอาหาร + เผาเครื่องปั้น |
| ครัว (`kitchen_01`…`04`) | cook 60 + kitchen 15–60 | สูตรสูงสุด |

เครื่องมือก็ไล่ระดับเหมือนกัน — สูตรระบุระดับ 1–60 แต่ไอเทมของ server เรายังเป็นเลเวล 1 ทุกชิ้น
จึงแปลงเป็น **ชั้นวัสดุ 1–3** แทน (หิน/ไม้ = 1 · กระดูก = 2 · โลหะ = 3):
ระดับ ≤15 → ชั้น 1 · ≤40 → ชั้น 2 · มากกว่านั้น → ชั้น 3
(ดู `RequiredTierOf` / `CraftToolTierOf` ใน `ServerPlayer.Crafting.cs`)

## 4. สูตร 3 ชนิด — และรองรับแค่ 2

ข้อมูลเกมแบ่งสูตรด้วยฟิลด์ `type`:

| ชนิด | จำนวน | ความหมาย | สถานะ |
|---|---:|---|---|
| 0 = Craft | 625 | ได้ของใหม่ตาม `prototype_id` (ปรับตามวัตถุดิบได้ด้วย `prototypes`) | ✅ ทำได้ |
| 1 = Modify | 73 | **แปรรูปของเดิม** — ย่าง/ต้ม/นึ่ง/ทอด/ตากแห้ง/รมควัน | ✅ ทำได้ |
| 2 = Reform | 22 | แก้ทรง/ย้อมเสื้อ ต้องมีระบบ reform slot ก่อน | ❌ ปฏิเสธพร้อมข้อความ |

### สูตรแปรรูป (type 1) ทำงานยังไง

ของในช่อง `base` 1 ชิ้นเข้าไป ได้ของชิ้นเดิมที่ **ไม่ดิบแล้ว** ออกมา:
prototype เท่าเดิม (`meat` ยังเป็น `meat`) แต่ **ตัด tag `raw_food` ทิ้งแล้วเติม `taste_good`**
ตามที่ข้อมูลเกมกำหนดไว้เอง (tag `raw_food` มี `effect_off: 'taste_good'`)

> ⚠️ เคยลองอีกทางคือประกอบชื่อ `สูตร_tag` (skewer + meat = `skewer_meat`) แล้ว**ใช้ไม่ได้** —
> `skewer_meat` ในข้อมูลเกมติด tag `blunt_onehand` อย่างเดียว (เป็นโมเดลของที่ถือ ไม่ใช่ของกิน)
> ย่างเนื้อแล้วจะได้ของที่กินไม่ได้ จึงเลิกใช้

สภาพ "สุกแล้ว" ถูกเซฟลงไฟล์ด้วย (`ItemSave.Processed`) ไม่งั้นออกเกมแล้วเข้าใหม่เนื้อย่างจะกลับเป็นเนื้อดิบ

## 5. กินแล้วได้อะไร

ค่าทั้งหมดมาจาก `FoodData` (ข้อมูลจริงของเกม) คูณสเกลใน `data/config.json` หัวข้อ `Food`
เพราะสเกลของเกมต้นฉบับใหญ่กว่าหลอดของเรามาก (ความล้า −150 ทั้งที่หลอดเราเต็มแค่ 100)

```json
"Food": {
  "EnergyScale": 0.5,          // สตามินาที่ได้ = ค่าในข้อมูลเกม × ตัวนี้
  "FatigueScale": 0.1,         // −150 ในข้อมูลเกม = ลดความล้า 15 ของเรา
  "HealthScale": 1.0,
  "RawFoodEnergyScale": 0.6,   // ของดิบให้พลังแค่ 60% ของของสุก
  "RawFoodFatigue": 3.0,       // กินดิบแล้วล้าเพิ่ม (ท้องไม่ดี)
  "DigestScale": 1.0           // ตัวคูณเวลาย่อย
}
```

**นี่คือจุดที่ทำให้ต้องทำอาหาร** — ตัวเลขจริงที่วัดได้จาก `--cook-check`:

| ของ | กินดิบ | ย่างแล้ว |
|---|---:|---:|
| เนื้อ (`meat`) | +18.9 | **+31.5** |
| เนื้อกิ้งก่า | +18.9 | **+31.5** |
| ปลา | +15.0 | **+25.0** |
| เนื้อต้ม (`boiled_meat`, สูตร Craft) | — | **+40.0** |

และมี **เวลาย่อย** (`digestivetime` ของเกม) — กินติด ๆ กันไม่ได้ ไม่งั้นรัวกินทั้งกระเป๋ารวดเดียว

## 6. เปิด/ปิดระบบ

`data/config.json` → `Features.Cooking` (hot-reload 5 วินาที)

ปิดอยู่ = สูตรหมวด `cook` **ถูกตัดออกจากรายการที่ส่งให้ client ด้วย** (ไม่ใช่แค่ปฏิเสธตอนกด)
ไม่งั้นผู้เล่นจะเห็นสูตรทำอาหารเต็มไปหมดแล้วกดไม่ได้สักอัน — ดู `BuildUnlocked` ใน `ServerPlayer.Skills.cs`

## 8. ของแถมที่แก้ไปด้วย

- **`AppearArtifact.Tags`** ส่ง tag จริงแล้ว ⇒ ปลดล็อกสูตรที่ต้องใช้โต๊ะทั้ง 587 อัน ไม่ใช่แค่สายทำอาหาร
- **วางของจากแคปซูลได้สถานะ `Completed`** (เดิมเป็น `Occupied` = แค่จองพื้นที่) ⇒ กองไฟที่วางจากแคปซูลใช้เป็นโต๊ะคราฟต์ได้จริง
- **เวลา/สตามินาของการคราฟต์เป็นค่าจริงของแต่ละสูตร** (เดิม 2 วินาที / 4 แต้มเท่ากันหมด)
- **สูตรที่ได้ทีละหลายชิ้นได้ครบ** (`count` เช่นน้ำซุปได้ 2 ถ้วย)
- **เลเวลขั้นต่ำของสูตรมีผลจริง** (`min_level`)
