# หน้า Admin Panel

หน้าเว็บควบคุมเซิร์ฟสำหรับเจ้าของเซิร์ฟ — เปิดที่ `http://<host>:<gateway-port>/admin?token=<admin token>`

- ไฟล์หน้าเว็บ: `server/admin/index.html` (ไฟล์เดียวจบ ไม่มี build step)
- route ฝั่งเซิร์ฟ: `server/ServerCore/Gateway.Admin.cs` (ของเดิม) + `Gateway.Admin.Ops.cs` (เพิ่ม 4 ก.ย. 2026)
- **เสิร์ฟจากดิสก์ทุก request** (`ServeAdminHtml`) ⇒ แก้ `index.html` แล้ว refresh เห็นผลทันที
  **ไม่ต้อง build ไม่ต้องรีสตาร์ตเซิร์ฟ** — ใช้ประโยชน์ข้อนี้ตอนแก้ UI ระหว่างมีคนเล่นอยู่
- token: เข้าครั้งแรกด้วย `?token=` แล้วหน้าเว็บจำใส่ localStorage ให้เอง

## 1. combobox สลับเกาะ/พอร์ต (island-mode)

เซิร์ฟเป็น "1 เกาะ = 1 process = 1 พอร์ต" (ดู `Islands.md`) หน้า admin จึงมี combobox บนสุด
บอกว่ามีเกาะอะไรบ้าง อยู่พอร์ตไหน ช่วงเลเวลเท่าไร มีคนกี่คน — เลือกแล้วเด้งไปพอร์ตนั้นทันที

**ที่มาของรายชื่อเกาะ 3 ชั้น** (ไล่ลงมาเมื่อชั้นบนไม่มี):

1. `GET /admin/islands` — ทะเบียนจริงจาก `data/islands.json`
2. ค่าติดมากับหน้า (`ISLE_FALLBACK`) — เผื่อเซิร์ฟยังเป็นรุ่นเก่าที่ไม่มี endpoint นี้
3. เกาะที่เพิ่มเองผ่านปุ่ม **"+ เพิ่มพอร์ต"** — เก็บใน localStorage ของเบราว์เซอร์
   (ไว้ใส่เซิร์ฟที่ไม่ได้อยู่ในทะเบียน เช่นเซิร์ฟเทส 8290)

**การสลับเกาะ = เปลี่ยนหน้าไปพอร์ตนั้น** ไม่ใช่ยิง API ข้ามพอร์ตทั้งใบ — ตั้งใจ เพราะแต่ละเกาะเป็นคนละโลก
คนละ config ทุก section (ผู้เล่น/แมพ/log/config) ต้องมาจากเกาะที่กำลังดูอยู่จริง ไม่งั้นแก้ config ผิดเกาะ

⚠️ **ต้องมีหัว CORS** — ตัวเลข "คนออนไลน์" บนแท็บของเกาะที่ไม่ได้เปิดอยู่ และทุกอย่างในหัวข้อ
"ศูนย์รวมทุกเกาะ" ยิงข้ามพอร์ต เบราว์เซอร์จะบล็อกถ้าเซิร์ฟไม่ส่ง `Access-Control-Allow-Origin`
เพิ่มไว้แล้วใน `GameCode/Durango.Offline/WebServer.cs` **เฉพาะ path ที่ขึ้นต้นด้วย `/admin`**
(ปลอดภัยเพราะทุก endpoint ใต้ `/admin/` ยังต้องมี `?token=` ที่ถูกต้อง)

## 2. ฟอร์มแก้ config

เดิมเป็น textarea JSON ดิบก้อนเดียว — พิมพ์ตกคอมมาเดียว config ทั้งไฟล์ไม่โหลด และไม่มีทางรู้ว่า
ช่องไหนหมายถึงอะไรถ้าไม่เปิด `ServerConfig.cs` อ่านเอง

ตอนนี้เป็นฟอร์มทีละช่อง:

| มีอะไร | รายละเอียด |
|---|---|
| คำอธิบายไทยข้างทุกช่อง | ดึงจาก `<summary>` ในโค้ดจริง — ไม่ได้เขียนซ้ำ |
| ค่าเริ่มต้น + ปุ่ม ↺ | จาก `Defaults()` ในโค้ด · กดคืนค่าเดิมได้ทีละช่อง |
| ช่องค้นหา | พิมพ์ไทยหรืออังกฤษ ค้นข้ามทุกหมวดพร้อมกัน |
| "เฉพาะที่ต่างจากค่าเริ่มต้น" | ดูรวดเดียวว่าเซิร์ฟนี้หมุนอะไรไปบ้าง |
| แถบเหลือง + ตัวนับ | ช่องที่แก้แล้วยังไม่บันทึก · แท็บหมวดขึ้น ● พร้อมจำนวน |
| ชนิดข้อมูล | bool = สวิตช์ · ตัวเลข = ช่องตัวเลข · array/object = กล่อง JSON เล็ก ๆ ตรงนั้น |
| โหมด JSON ดิบ | ปุ่มสลับ เผื่อต้องแก้อะไรที่ฟอร์มไม่ครอบคลุม |

**หลักสำคัญ**: ฟอร์ม**ไม่สร้าง JSON ขึ้นใหม่** แต่แก้ค่าลงบนก้อนที่โหลดมาแล้วส่งกลับทั้งก้อน
⇒ ช่องที่ฟอร์มไม่ได้เรนเดอร์ (ของใหม่ที่เซิร์ฟเพิ่มมา, ตารางยาว ๆ) ไม่หายไปไหน

### คำอธิบายมาจากไหน

```
python tools/gen-config-meta.py     # อ่าน ServerConfig.cs -> server/data/config-meta.json
```

- **ต้องรันใหม่ทุกครั้งที่เพิ่ม/แก้ช่องใน `ServerConfig.cs`** ไม่งั้นช่องใหม่จะขึ้นว่า "ยังไม่มีคำอธิบายในโค้ด"
- ผลลัพธ์วางไว้ใต้ `data/` ตั้งใจ — หน้าเว็บดึงผ่าน `/admin/data-file?name=config-meta.json`
  ที่มีอยู่แล้ว จึงไม่ต้องเพิ่ม route ใหม่ (= อัปคำอธิบายใหม่ได้โดยไม่ต้อง build เซิร์ฟ)
- ตอนนี้ครอบคลุม 21 หมวด · 251 ช่อง · มีคำอธิบาย 216 ช่อง (86%)

## 3. ศูนย์รวมทุกเกาะ

| ส่วน | ทำอะไร |
|---|---|
| ตารางทุกเกาะ | คน / TPS / RAM / uptime / digest ชุดข้อมูล ของทุกเกาะในตารางเดียว |
| ประกาศทุกเกาะ | ส่ง broadcast พร้อมกันทุกเกาะ (เดิมต้องไล่เปิดทีละพอร์ต) |
| ค้นหาผู้เล่นข้ามเกาะ | พิมพ์ชื่อ → บอกว่าอยู่เกาะไหน + ปุ่มกระโดดไปหน้า admin ของเกาะนั้น |
| เทียบ config ระหว่างเกาะ | โชว์เฉพาะค่าที่ตั้งไม่ตรงกัน + ปุ่ม "ดันค่านี้ไปทุกเกาะ" |

> เทียบ config เกิดจากเคสจริง: แพตช์ค่าความล้าลง `isle01` แล้วลืม `isle02`
> ⇒ `FatigueCostCombat` ต่างกัน 10 เท่าอยู่หลายวันโดยไม่มีใครเห็น

`digest` (`data_manifest_digest`) ที่ไม่ตรงกันระหว่างเกาะ = เกาะนั้นรันชุดข้อมูล/binary คนละรุ่น

## 3.5 หน้าแผนที่ = ที่เดียวจบสำหรับย้ายสิ่งก่อสร้าง

หัวข้อ POI ถูกยุบเข้ามาอยู่ใต้แผนที่ (4 ก.ย. 2026) — เดิมแยกกันคนละหัวข้อ ต้องอ่านพิกัดจากแผนที่
แล้วเลื่อนไปพิมพ์ตัวเลขในอีกที่

- กด **"ย้าย"** ที่แถวใดก็ได้ → เข้าโหมดย้าย (แถบเหลือง + วงสีฟ้ารอบตัวนั้นบนแผนที่)
- **คลิกจุดบนแผนที่** → ยืนยัน → ย้ายเลย · หรือกด "พิมพ์พิกัดเอง" ถ้าต้องการความแม่น
- ปุ่ม **"ใช้จุดที่คลิกบนแผนที่"** สำหรับช่องวาง POI ใหม่
- ย้ายแล้ว **อยู่ถาวร** (เก็บใน `world.json`) — `PlaceIslandPois()` ข้ามตัวที่มี id อยู่แล้ว

คำสั่งในเกมที่ทำอย่างเดียวกัน: `cheat poi here <id>` (ย้ายมาตรงที่ยืน) · `cheat poi move <id> <x> <y>` · `cheat poi tp <id>`

## 3.6 ไฟล์ข้อมูลของเกาะ (terrains)

อัป/แก้ `pois.yml` `herds.yml` `config.yml` `info.yml` ของแต่ละเกาะจากหน้าเว็บ — เลือกไฟล์จากเครื่อง
(อ่านเป็นข้อความมาใส่กล่องให้ตรวจก่อน) หรือพิมพ์เองก็ได้

- **ทำไมต้องมี**: เจอของจริงว่าเกาะหิมะบน VPS **ไม่มี `pois.yml` เลย** ⇒ เซิร์ฟสุ่มตำแหน่ง POI ให้เอง
  แล้วท่าเรือไปโผล่ห่างจุดเกิด 232 tile · เดิมทางแก้เดียวคือ scp ขึ้นเครื่อง
- `/admin/data-file` เดิมรับเฉพาะ `.json` ใต้ `data/` ⇒ ไฟล์ `.yml` ของเกาะเข้าไม่ได้ จึงแยก endpoint ใหม่
- กันไว้: เขียนได้เฉพาะ 4 ชื่อไฟล์ข้างบน · ห้าม `..` หรือ `/` ในชื่อเกาะ · ต้องอยู่ใต้ `terrains/extracted` เท่านั้น
- แปลง CRLF เป็น LF และเขียน UTF-8 ไม่มี BOM ให้อัตโนมัติ (ตัวอ่าน yaml ของเราคาดแบบนี้ และ BOM ทำให้ key แรกอ่านไม่ออก)
- สำรองไฟล์เดิมเป็น `.bak-<เวลา>` ทุกครั้ง
- ⚠️ **มีผลตอนเปิดเซิร์ฟใหม่** และเฉพาะ POI ที่ยังไม่เคยถูกวาง (ถ้าวางไปแล้วต้องลบตัวเก่าก่อน)

## 4. งานดูแลอื่น ๆ

### ระงับการเข้าเล่น (แบน)
- เดิมมีแค่ "เตะ" ซึ่งตัดการเชื่อมต่อเฉย ๆ — กด Connect ใหม่ก็กลับเข้ามาได้ทันที
- ตอนนี้แบนเก็บถาวรที่ `data/bans.json` (**ทุกเกาะใช้ไฟล์เดียวกัน ⇒ แบนทีเดียวติดทุกเกาะ**)
- ตรวจตอน `Auth` ใน `GameServer.cs` — หลัง `TryAuthorize` เพราะต้องได้ entity id จริงจาก session ก่อน
- แบนได้ทั้งถาวรและมีวันหมดอายุ · ถ้าคนนั้นออนไลน์อยู่จะถูกเตะออกให้ทันที
- โค้ด: `server/ServerCore/BanList.cs`

### รีสตาร์ตแบบนับถอยหลัง
- ประกาศในเกมที่ 5 นาที / 3 นาที / 1 นาที / 30 วิ / 10 วิ แล้วค่อยปิด process
- systemd (`Restart=always`) เปิดให้ใหม่เอง — **ถ้า unit ยังเป็น `Restart=on-failure` เซิร์ฟจะไม่กลับมา**
- โค้ด: `RestartCountdown()` ใน `Gateway.Admin.Ops.cs`

### กราฟย้อนหลัง 12 ชั่วโมง
- `ServerStats` เก็บ ring buffer 720 จุด ทุก 1 นาที (คน / TPS / RAM)
- เก็บในหน่วยความจำอย่างเดียว ตั้งใจ — **รีสตาร์ตแล้วเริ่มนับใหม่** ไม่คุ้มที่จะเขียนดิสก์ทุกนาที
- วาดเป็น SVG ในหน้าเว็บเอง ไม่โหลดไลบรารีจากเน็ต (เซิร์ฟอาจไม่มีเน็ตออก)

### ตารางบัพ/ดีบัพ
- อ่าน `data/assets/survival/status_effects.json` ของเกมจริง (372 ตัว) ค้นหา/กรองบัพ-ดีบัพได้
- ปุ่ม "ลองใส่ตัวเอง" = ยิง `cheat effect <id>` (ต้องเปิด `--enable-cheat`)
- ⚠️ เซิร์ฟเราคิดผลจริงให้แค่ `rest` / `thirsty` / `drink_water` / `satiety_high`
  ที่เหลือส่งไอคอนให้ client ได้แต่ยังไม่มีผลตัวเลข (ดู `ServerPlayer.Group2.cs → BuildEffectDetails`)

### ทะเบียนเกาะ
- แก้ `data/islands.json` จากหน้าเว็บ (ตรวจว่ามี `Id` และ `GatewayPort` ที่ถูกต้องก่อนเขียน + สำรองไฟล์เดิม)
- **มีผลตอนเปิดเซิร์ฟใหม่เท่านั้น** — แต่ละเกาะอ่านทะเบียนตอนบูต

## ของที่ต้องระวังตอน deploy

1. `index.html` + `config-meta.json` **อัปได้ระหว่างคนเล่นอยู่** (เสิร์ฟจากดิสก์ / อ่านผ่าน data-file)
2. endpoint ใหม่ทั้งหมดกับหัว CORS อยู่ใน **binary** ⇒ ต้อง build + สลับไฟล์ + รีสตาร์ต
3. หน้าเว็บออกแบบให้ทำงานกับเซิร์ฟรุ่นเก่าได้ — endpoint ที่ยังไม่มีจะขึ้นข้อความว่า
   "ต้องอัปเซิร์ฟก่อน" แทนที่จะพังทั้งหน้า
4. systemd ต้องเป็น `Restart=always` ไม่งั้นปุ่มรีสตาร์ตจะปิดเซิร์ฟแล้วไม่กลับมา
   (`/etc/systemd/system/durango*.service` แก้ให้แล้ว 4 ก.ย.)
5. `announce-restart.sh` รับพอร์ตเป็นอาร์กิวเมนต์แล้ว — `ExecStop` ของแต่ละเกาะต้องส่งพอร์ตตัวเอง
   (เดิม hardcode 8190 ⇒ ตอนรีสตาร์ตเกาะหิมะ ประกาศไปโผล่ผิดเกาะ)
