# บันทึก: ทำไม "ขวาน" ถึงหาย/กลับมาในเมนูคราฟต์

ไฟล์นี้มีไว้กันงงซ้ำ — เรื่องขวานหายเกิดขึ้นมาแล้ว **2 สาเหตุที่ไม่เกี่ยวกันเลย** ในเซสชันนี้ ถ้าเจอ
"ขวานหาย" อีก ให้เช็คตามลำดับข้างล่างก่อนไล่หาสาเหตุใหม่

## สาเหตุที่ 1 (เจอแล้ว แก้แล้ว ถาวร) — client ซ่อนสูตรที่วัตถุดิบไม่พอ

**ไฟล์:** `client/Durango.UI/RecipeListWidget.cs`, ฟังก์ชัน `EnumerateItems()`

**อาการ:** ขวานไม่โผล่ในเมนูคราฟต์เลย ไม่ว่าจะปลดล็อกสูตรไว้เท่าไหร่ก็ตาม

**สาเหตุจริง:** โค้ดเดิมมี
```csharp
if (!IsFavorites && blocker == CraftBlocker.Materials)
{
    continue;   // วัตถุดิบไม่พอ = ไม่ต้องโชว์ (ซ่อนไปเงียบๆ)
}
```
ขวานต้องใช้วัตถุดิบ 3 อย่าง (blade + เชือก + ด้าม) — ไม่มีใครมีของครบเลยตั้งแต่เริ่ม เลยไม่เคยเห็นมันโผล่
เข้าใจผิดว่าเป็นบั๊กเรื่อง resources.assets เสีย (ลองสลับไฟล์ฐานเก่าดูด้วยซ้ำ ไม่ช่วยอะไร — ดู HANDOFF.md
รอบ 24 ส.ค. 2026 23:30) ที่จริงแล้วสูตรทำงานถูกต้อง 100% แค่ UI ไม่ยอมโชว์ให้เห็น

**การแก้:** ลบเงื่อนไข `continue` ตัวนี้ทิ้ง (คอมเมนต์อธิบายไว้แทนที่โค้ดเดิม) — **ยังไม่ได้แก้กลับ** ยังอยู่
เหมือนเดิมจนถึงตอนนี้ ถ้าขวานหายอีกและไม่ใช่เพราะสาเหตุนี้ ให้เช็คว่าไฟล์นี้ยังไม่มี `continue` ตัวนี้กลับมา
ก่อน (`git diff`/`git log -p -- client/Durango.UI/RecipeListWidget.cs`)

**หมายเหตุ:** การแก้นี้ทำให้ของทุกอย่างที่ "วัตถุดิบไม่พอ" โชว์แบบจางๆ แทนที่จะซ่อน — เป็นการเปลี่ยน
พฤติกรรมถาวรตามที่เจ้าของสั่ง ("อยากให้เห็นสูตรครบเหมือนโหมดออฟไลน์") ไม่ใช่ workaround ชั่วคราว

## สาเหตุที่ 2 (กำลังไล่อยู่ ณ 25 ส.ค. 2026) — รายการปลดล็อก + ระบบสกิล

**ไฟล์:** `server/ServerCore/ServerPlayer.Skills.cs` (`BuildUnlocked()`), `RecipeUnlockData.cs`

**อาการ:** หลังแก้สาเหตุที่ 1 แล้ว ขวานโผล่ปกติ (เทสยืนยันหลายรอบ รวมถึงรอบล่าสุดที่เห็นในภาพหน้าจอ
"ขวานมือเดียวที่ทำขึ้นเอง"/"ขวานสองมือที่ทำขึ้นเอง" ในหมวดอาวุธ) — แต่เจ้าของรายงานว่าเจอขวานหายอีกครั้ง
ในบางสถานการณ์ และตั้งข้อสังเกตว่า **"ขวานคราฟได้ตอนเลเวล 2"** ชวนให้สงสัยว่าเป็นเรื่อง**ระบบสกิลไม่
อัพเดตทันเวลา** (ปลดล็อกจริงแต่ client/server sync ช้า หรือคำนวณ `_knownSkills`/`RecipeUnlockData.Collect`
ผิดจังหวะ) — **ยังไม่ได้พิสูจน์/สรุปสาเหตุจริง**

**บริบทที่เกี่ยวข้อง:** ระหว่างที่ไล่เรื่องนี้ มีการทดลองเปลี่ยน `BuildUnlocked()` หลายรอบ:
1. เดิม: ใช้ `ServerConfig.Current.Starter.Recipes`/`Blueprints` (34/12 อันจาก `data/config.json`)
   — **`assembled_axe_one_01` อยู่ในลิสต์นี้แน่นอน** (เช็คแล้ว 25 ส.ค. 2026)
2. ลองเปลี่ยนเป็น `RecipeData.AllRecipeIds`/`AllBlueprintIds` (เต็ม 720/570) — ขวานอยู่แน่นอนเพราะ
   เป็นลิสต์เต็ม แต่เมนูรกไปด้วยของไม่เกี่ยวข้อง
3. ลองคัดเป็น `StarterCuratedContent` (457/515 ตาม 3 แนวเล่น + จำกัด Lv.30 + ซ่อนของต้องใช้โต๊ะ) —
   `assembled_axe_one_01` (MinLevel 1, หมวด weapon_and_tool) **อยู่ในลิสต์นี้แน่นอน** เช่นกัน (เช็คแล้ว)
   แต่ระหว่างขั้นตอนนี้เจอว่าโค้ดคัด Blueprints ยังมีของหลุด 60 อัน (ไม่เกี่ยวกับขวาน แต่เป็นสาเหตุที่เจ้าของ
   ตัดสินใจย้อนกลับไปจุดที่ 1 ก่อน — ดูหัวข้อ "สถานะปัจจุบัน" ด้านล่าง)

**สรุปสำคัญ**: ทั้ง 3 ลิสต์ (34/12, 720/570, 457/515) ล้วนมี `assembled_axe_one_01` อยู่ — แปลว่า **ปัญหา
"ขวานหาย" รอบล่าสุดนี้ไม่ได้เกิดจากลิสต์ปลดล็อกที่เลือกใช้** ต้องมาจากอย่างอื่น ตรงกับทฤษฎีของเจ้าของที่
สงสัยระบบสกิล — ควรเช็คเป็นลำดับแรกตอนกลับมาไล่เรื่องนี้ต่อ:
1. `BuildUnlocked()` คิดใหม่ทุกครั้งที่ถาม (ไม่แคช ตามคอมเมนต์ในโค้ด) — ตัด "แคชเก่า" ออกจากสมมติฐานได้
2. เช็ค `_knownSkills` ของตัวละครทดสอบ ตอนเลเวล 1 vs เลเวล 2 — มีสกิลอะไรเปลี่ยนไหม มี research ค้าง
   คิวอยู่ไหม (`ResearchTimeFor`/`ResearchingFor` ใน `ServerPlayer.Skills.cs`)
3. เช็คว่า client sync ทัน server ไหม — `SendSkills()`/`GetRecipes` ส่งออกไปตอนไหน เทียบกับตอนที่
   client เรียก `ResetCategories()` ใหม่ (`StatisticsSystem_LevelChanged` ใน `RecipeSelectorGroup.cs`
   จะ reset categories ทุกครั้งที่เลเวลเปลี่ยน — ถ้า server ส่ง unlocked list ช้ากว่า level-up event
   client อาจ reset ด้วยข้อมูลเก่าไปก่อน)
4. เช็คว่า `assembled_axe_one_01` ต้องมี "ability"/สกิลอะไรกำกับอยู่ไหม (ข้อมูลเกมจริงจากมือถือมี field
   `required_ability` — ของขวานคือ `210` — ต้องเช็คว่า skill id 210 คืออะไรกันแน่ ระดับเท่าไหร่ถึงจะพอ)

## สถานะปัจจุบัน (25 ส.ค. 2026)

`BuildUnlocked()` ถูกสั่งให้ **ย้อนกลับไปใช้ `ServerConfig.Current.Starter.Recipes`/`Blueprints` (34/12
อันดั้งเดิม)** แล้ว เพื่อตัดตัวแปรเรื่องลิสต์ปลดล็อกออกจากสมการก่อนไล่สาเหตุที่ 2 ต่อ — `StarterCuratedContent.cs`
(457/515, งานคัดตาม 3 แนวเล่น) ยังอยู่ในโค้ดเผื่อกลับมาใช้ทีหลัง แต่ **ไม่ได้ต่อกับ `BuildUnlocked()` แล้ว
ตอนนี้** — ดู `docs/server/Starter-Recipes-Report.md` สำหรับรายละเอียดงานคัดที่ค้างอยู่ (รวมบั๊ก blueprint
หลุด 60 อันที่เจอระหว่างทางแต่ยังไม่ได้ merge กลับ)
