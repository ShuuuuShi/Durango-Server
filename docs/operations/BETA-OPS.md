สำหรับคนที่ดูแลเซิร์ฟตอนเปิดให้คนนอกเข้ามาเล่นจริง

## 1. เปิดเซิร์ฟ

```bash
cd "C:\Users\thana\Desktop\Durango Opencode\server"
dotnet run -- --whitelist data/whitelist.txt
```

ค่าที่ได้จากคำสั่งนี้ (ค่าเริ่มต้นทั้งหมด = ค่าที่ปลอดภัย):

| อย่าง | สถานะ | ทำไม |
|---|---|---|
| cheat (`Cheat` packet) | **ปิด** | ไม่ใส่ `--enable-cheat` = ใครยิงมาก็โดนปฏิเสธ |
| radiotower (พอร์ตเกม+1) | **ปิด** จนกว่าจะใส่ `--radiotower` | ตรวจ session token แล้ว เปิดได้ปลอดภัย (M-5 แก้ 2 ก.ย. 2026) |
| ผูก entity id กับ IP | **เปิด** | คนแรกที่ใช้ id ไหน = เจ้าของ id นั้น |
| บทสนทนา NPC / ระบบสอนเล่น | **ปิด** | `RegionRole=Sandbox` |
| เพดาน connection | 32 เส้น (4 ต่อ IP) | |
| rate limit | 120 packet/วินาที ต่อเส้น | เตือน 3 หน้าต่างติดกันแล้วเตะ |
| auto-save | ทุก 60 วินาที (เฉพาะที่เปลี่ยน) | Ctrl+C ก็เซฟให้ก่อนปิด |

⚠️ **ห้ามเปิดโดยไม่ใส่ `--whitelist`** — ถ้าไม่มีรายชื่อ ใครก็ตั้ง entity id เองได้
แปลว่ามีไฟล์เซฟใหม่ 1 ไฟล์ต่อ id ที่ใครสักคนคิดขึ้นมา (ดิสก์โตไม่จำกัด)

### เพิ่มผู้เล่นเข้ารายชื่อ

`server/data/whitelist.txt` — บรรทัดละ 1 entity id หรือชื่อตัวละคร · `#` = คอมเมนต์
**ไม่ต้องรีสตาร์ทเซิร์ฟ** ไฟล์นี้ hot-reload เมื่อเวลาแก้ไขเปลี่ยน

ตอนนี้ในไฟล์มีชื่อของบอทเทสอยู่ด้วย (`gp-check-*` `multi-*` `farmbot-*`)
เอาออกได้ถ้าไม่อยากให้ใครเข้าด้วยชื่อพวกนี้ — แต่ถ้าเอาออกแล้ว `--gp-check` / `--multi-check` จะรันไม่ได้

## 2. ดูว่าเซิร์ฟยังดีอยู่ไหม

บรรทัดสถิติออกทุก 30 วินาที:

```
[loop] 120 tps, ผู้เล่นออนไลน์ 3, สัตว์ 34 ตัว (+ซาก 2), RAM 32 MB
```

| ตัวเลข | ปกติ | ถ้าผิดปกติแปลว่า |
|---|---|---|
| tps | 118-120 | ต่ำกว่า 100 = มีอะไรกิน main loop (ดู log ว่ามี `[error]` ซ้ำ ๆ ไหม) |
| สัตว์ | 34 ตัว | ต่ำกว่านี้นาน ๆ = คิวเกิดใหม่ค้าง (ปกติกลับมาครบใน 60 วินาทีหลังตัวสุดท้ายตาย) |
| (+ซาก n) | 0-6 ตัว | ซากที่ยังแล่ได้ อยู่ได้ 150 วินาทีแล้วหายเอง · ค้างเยอะผิดปกติ = มีคนฆ่ารัวแต่ไม่แล่ |
| RAM | ~30-70 MB | โตขึ้นเรื่อย ๆ ไม่หยุด = มี state ที่ไม่ถูกล้าง |

บรรทัดที่ควรสังเกตใน log:

| ข้อความ | หมายถึง |
|---|---|
| `[gameserver] ปฏิเสธ <ip>: เต็มเพดาน` | มีคนต่อเกิน 32 เส้น หรือ IP เดียวเกิน 4 |
| `[gameserver] เตะ <ชื่อ>: ยิง packet เร็วเกิน` | rate limit ทำงาน (คนนั้นใช้ tool หรือเน็ตพัง) |
| `[move] ปฏิเสธ <ชื่อ>: ขยับ ... หน่วย` | ความเร็วเกิน — เจอบ่อยกับคนเดียว = สงสัยโกง |
| `[touch]/[collect] ปฏิเสธ` เยอะผิดปกติ | client เก่า/แก้แล้ว หรือมีคนลองยิง packet เอง |
| `[error] <ระบบ>` | exception ที่ H-4 จับไว้ — **เซิร์ฟไม่ตาย** แต่ต้องตามดูว่าเกิดจากอะไร |

## 3. เทสก่อนเปิดทุกครั้ง (ใช้เวลา ~2 นาที)

```bash
cd "C:\Users\thana\Desktop\Durango Opencode\server"
dotnet run -- --whitelist data/whitelist.txt --enable-cheat --admin bot-op --max-connections-per-ip 8

# อีกหน้าต่าง
cd "C:\Users\thana\Desktop\Durango Opencode\test-client"
dotnet run --no-build -- --gp-check      # ต้องได้ 36/36
dotnet run --no-build -- --multi-check   # ต้องได้ 9/9

# ระบบที่ดิน — 39 ข้อ (ต้องเปิดเซิร์ฟด้วย --enable-cheat เพราะใช้ cheat tp / cheat save)
dotnet run --no-build -- --estate-check 127.0.0.1 8191 8190
#   ท้ายรันพิมพ์ entityId ที่ทิ้งแปลงไว้ → รีสตาร์ทเซิร์ฟ แล้วเช็คว่าที่ดินยังอยู่ (5 ข้อ)
dotnet run --no-build -- --estate-reload-check 127.0.0.1 8191 8190 <entityId>

# พอร์ตแชท — 12 ข้อ (เฉพาะตอนเปิดเซิร์ฟด้วย --radiotower)
dotnet run --no-build -- --radiotower-check 127.0.0.1 8192 8190
```

> ⚠️ **สถานะ gp-check ตอนนี้ (2 ก.ย. 2026): ผ่าน 31 ตก 5** — ตกเรื่องแตะของธรรมชาติไกลเกินเอื้อม,
> ลบของธรรมชาติที่ไม่เคยแตะ (chunk รอบจุดเกิดไม่มีของธรรมชาติเหลือแล้วในเซฟเทสชุดนี้) และ 3 ข้อ
> เรื่องเลเวลที่ client อ้าง (ตัวเช็คเห็นเลเวล -1 = ไม่ได้ `AppearPlayer` ของตัวเอง)
> **ไม่เกี่ยวกับระบบที่ดิน/แชท** — ต้องตามแยกต่างหากก่อนเคลม 36/36

แล้ว**ปิดแล้วเปิดใหม่ด้วยคำสั่งของข้อ 1** (ไม่มี `--enable-cheat`) ก่อนให้คนนอกเข้า

## 4. เวลาเกิดปัญหา

| อาการ | ทำอะไร |
|---|---|
| คนเข้าไม่ได้ (`ไม่ได้อยู่ในรายชื่อที่อนุญาต`) | เพิ่มชื่อใน `data/whitelist.txt` (ไม่ต้องรีสตาร์ท) |
| คนเปลี่ยนเน็ตแล้วเข้าไม่ได้ (IP ผูกไว้แล้ว) | ลบ `saves/accounts/<id>.json` หรือเปิดด้วย `--no-ip-bind` |
| เครื่องอื่นในวงเข้าไม่ได้ | gateway ผูกได้แค่ loopback — รัน PowerShell as Admin ครั้งเดียว:<br>`netsh http add urlacl url=http://*:8190/ user=Everyone` |
| อยากดูของ/ตำแหน่งผู้เล่นคนหนึ่ง | เปิดไฟล์ `saves/players/<id>.json` |
| เซิร์ฟค้าง/ต้องปิด | **Ctrl+C** แล้วรอ `[save] ... ปิดเรียบร้อย`; ก่อน deploy/schema/world/economy change ให้ snapshot ทั้ง save root ตาม [`S0-FOUNDATION.md`](../server/S0-FOUNDATION.md#backup-and-restore-procedure). อย่า kill process ทิ้ง เว้นแต่ graceful shutdown timeout แล้วบันทึกว่า dirty interval สูงสุด 60 วินาทีอาจหาย |
