01สรุปการตัดสินใจ

เราเลิกใช้ระบบมอดทั้งหมด ไม่มีโฟลเดอร์ mods/ ในชุดแจกอีกแล้ว ทุกอย่างที่เคยเป็นมอด ย้ายไปแก้ที่ซอร์สของ Assembly-CSharp.dll โดยตรง แล้วบิลด์ใหม่

เหตุผลไม่ใช่เรื่องรสนิยม แต่เพราะมอดพึ่งไฟล์นอกตัวเกม ซึ่งหลุดหายได้จริงและเคยหายมาแล้ว อาการตอนหายคือ ผู้เล่นเห็นเมนูค้างที่ “กำลังตรวจสอบ…” ต่อเซิร์ฟไม่ได้ หาตัวละครไม่เจอ โดยไม่มี error ขึ้นให้เดาถูกเลยว่าเกิดอะไร ต้องไปไล่ log ถึงจะรู้ว่าไฟล์ DLL หายไปเฉย ๆ

แพตช์ไม่มีปัญหานี้ เพราะโค้ดฝังอยู่ในตัวเกม — ถ้าเกมเปิดได้ แปลว่าแพตช์อยู่ครบแน่นอน ไม่มีสถานะกึ่ง ๆ ให้ผู้เล่นเจอ

02มอดกับแพตช์ต่างกันยังไง

ทั้งสองทางเขียน C# เหมือนกัน ต่างกันที่โค้ดไปอยู่ตรงไหน และเข้าถึงตัวเกมได้ลึกแค่ไหน

เลิกใช้แล้ว

มอด

ข้อดี

  • แก้แล้วไม่ต้องแตะไฟล์เกม อัปเดตทีละตัวได้
  • ผู้เล่นถอดออกเองได้ถ้าไม่ชอบ

ข้อเสีย

  • เข้าถึงได้แค่ของที่เป็น public หรือต้องงัดผ่าน reflection ซึ่งช้าและพังเงียบ
  • แก้บั๊กที่อยู่ข้างในเมธอดที่คอมไพล์แล้วไม่ได้เลย — บั๊กคราฟต์ติดตรงนี้อยู่หลายวัน
  • ไฟล์หาย = ฟีเจอร์หายเงียบ ไม่มีสัญญาณเตือน
  • เวอร์ชันมอดกับตัวเกมหลุดกันได้ ต้องมาไล่จับคู่เอง
  • ถ้าจะแก้พฤติกรรมเดิมต้อง override เมธอด ซึ่งทำให้เกมดับ

ใช้อยู่ตอนนี้

แพตช์ซอร์ส

ข้อดี

  • แก้ได้ทุกบรรทัด รวมข้างในเมธอด
  • เรียกคลาสของเกมตรง ๆ ไม่ต้อง reflection ให้เปลืองและเสี่ยง
  • คอมไพเลอร์จับพิมพ์ผิด/ชนิดข้อมูลผิดให้ตั้งแต่ตอนบิลด์
  • ไฟล์เดียว หายไม่ได้ เกมเปิดได้ = แพตช์ครบ
  • เขียนคอมเมนต์กำกับไว้ในที่เดียวกับโค้ด อ่านย้อนได้ว่าแก้ทำไม

ข้อเสีย

  • ต้องบิลด์ใหม่แล้วก๊อป DLL ทับทุกครั้ง (ต้องปิดเกมก่อน)
  • แตะ asset ไม่ได้เลย — ทำ UI ใหม่/โมเดล/เสียง ไม่ได้
  • ผู้เล่นถอดออกไม่ได้ ถ้าแพตช์พังคือพังทั้งเกม

03สถานะฟีเจอร์ทั้งหมด

ใช้ได้ เทสแล้วเห็นผลจริง · ยังไม่ได้เทส เขียนเสร็จแล้วแต่ยังไม่มีใครกดยืนยัน · ยังไม่ได้ทำ หายไปพร้อมมอด ยังไม่ได้ย้ายมา

ความสามารถสถานะรายละเอียด
การเข้าเกม
เข้าเซิร์ฟจากเมนูในเกม ยังไม่ได้เทส ปุ่ม DurangoTH Community Server อ่าน server.txt แล้วต่อให้เลย เดิมมันอ่านแต่ IP ที่ผู้เล่นเคยกรอกเอง ซึ่งคนโหลดใหม่ไม่มี เลยตกไปที่ 127.0.0.1 แล้วค้าง
ชื่อเซิร์ฟในเมนู ใช้ได้ เดิมเป็น Dinoworld Server ที่หลุดมาจากโค้ดเก่า แก้ที่ซอร์สแล้ว ไม่ใส่แท็กสี NGUI เพราะบางหน้าจอไม่รองรับแล้วจะโชว์แท็กดิบให้เห็น
ตัวละครไม่หายตอนล็อกอิน ใช้ได้ ผูกบัญชีกับตัวละครแล้ว และรองรับคนที่ IP เปลี่ยนตลอด (จับคู่ระดับวง /24) เดิมต้องสร้างตัวใหม่แทบทุกครั้งที่เข้า
ระบบหลักในเกม
คราฟต์ของ · สร้างบ้าน ใช้ได้ เดิมกดยืนยันสูตรแล้ว NullReferenceException ทุกครั้ง เพราะโค้ดอ้างชิ้นส่วน UI ที่ไม่มีอยู่จริงในเลย์เอาต์นั้น ใส่ null guard 42 จุดใน ExpectResultWidget แล้ว ครอบเส้นทางสร้างบ้านด้วย
ตัวเลขดาเมจตอนตี ใช้ได้ เซิร์ฟไม่เคยส่งแพ็กเก็ต Damaged ให้คนที่เห็นเหตุการณ์ เพิ่มการกระจายแล้ว
ข้อความกระเป๋าเต็ม ใช้ได้ เดิมโชว์ handler 144 ดิบ ๆ ให้ผู้เล่นเห็น ซึ่งเป็นข้อความ debug ไม่ใช่ error จริง ตอนนี้บอกจำนวนช่องที่ใช้อยู่ (ของทุกชิ้นกินช่องละ 1)
สัตว์มุดเข้าไปในหิน ใช้ได้ เพิ่มระยะเลี่ยงสิ่งกีดขวางเป็น 6 ช่องฝั่งเซิร์ฟ ทั้งตอนเดินและตอนเลือกจุดหมาย
ระยะโหลดแมพ ยังไม่ได้เทส ขยาย 5×5 เป็น 9×9 chunk ตามที่เซิร์ฟบอกมาทาง /knock แก้อาการ “วิ่งไปแล้วแมพรีเฟรช” ตอนนี้ตั้งค่าตั้งแต่ตอนสร้าง pool ไม่ใช่สร้างใหม่ทับทีหลังแบบที่มอดทำ
ปลดล็อกเมนู สกิล/คราฟต์/เควส ยังไม่ได้เทส ดึงค่า enabled_menus จากเซิร์ฟมาเก็บไว้แล้ว แต่ยังไม่ได้เอาไปใช้จริง
ยังหายอยู่ — เคยอยู่ในมอด
ประกาศจากแอดมิน ยังไม่ได้ทำ รับแพ็กเก็ต Info มาแสดงบนจอด้วย UI ของเกมเอง ฝั่งเซิร์ฟส่งได้อยู่แล้ว รอฝั่งเกมมารับ
วาปข้ามเซิร์ฟ A/B ตอนรีสตาร์ต ยังไม่ได้ทำ ฝั่งเซิร์ฟเสร็จแล้ว — นับถอยหลัง เซฟ ส่ง ##goto แล้วย้ายผู้เล่นโดยคงพิกัดเดิม ใช้กลไกเดียวกับการย้ายเกาะของเกม ใช้เวลา 1.1 วินาที แต่ตัวรับคำสั่งอยู่ในมอด
รายชื่อเซิร์ฟมุมจอ + ต่ออัตโนมัติ ยังไม่ได้ทำ เดิมโชว์ชื่อเซิร์ฟ สถานะ และจำนวนคนออนไลน์ ตอนนี้ต้องกดเข้าเองจากเมนู ซึ่งตรงกับที่ตกลงกันไว้ว่าไม่ต้องต่ออัตโนมัติ
บอทขับตัวละครอัตโนมัติ ใช้ได้ ยังเป็นมอดอยู่ ใช้เฉพาะเครื่องพัฒนา ไม่ได้ใส่ไปในชุดแจก ใช้ไล่เทสระบบแทนคนกดเอง

04ข้อห้ามที่พิสูจน์แล้ว

สามข้อนี้ไม่ใช่ข้อสงสัย แต่เจอซ้ำจนสรุปได้แล้ว อย่าเสียเวลาลองใหม่

ห้าม override เมธอดของเกม

ใช้ Harmony หรือ method override เมื่อไหร่ เกมดับทันทีตั้งแต่ก่อนถึงหน้าไตเติ้ล ไม่มี error ให้ดู log จบดื้อ ๆ กลางคัน Mono ของเกมรุ่นนี้รับไม่ได้ เจอมาแล้ว 4 ครั้ง จาก 4 จุดที่ไม่เกี่ยวกันเลย

ห้ามเดาว่าฟิลด์ที่ว่างคือของเสีย

เคยเขียนตัวไล่เติมค่าให้ฟิลด์ UI ที่เป็น null อัตโนมัติ แล้วมันไปเติม _selectedWorkbench ให้ด้วย ผลคือเกมนึกว่ามีโต๊ะคราฟต์ทั้งที่ไม่มี = ช่องโกงที่เราสร้างขึ้นเอง

ห้ามเชื่อไคลเอนต์

โค้ดฝั่งเกมอยู่ในเครื่องผู้เล่น แก้ได้หมด ทุกอย่างที่มีผลต่อของในเกมต้องให้เซิร์ฟตัดสิน ฝั่งเกมมีหน้าที่แค่วาดภาพกับส่งคำขอ ตอนทำ UI ให้ถามก่อนเสมอว่าถ้าคนแก้ฝั่งนี้ได้ เขาจะได้อะไรฟรี

  • ต้อง build เกมใหม่ทั้งก้อน แพตช์ที่สะสมมาต้องทำใหม่หมด
  • เสี่ยงพังระบบอัปเดตที่ปล่อยให้ผู้เล่นไปแล้ว

ที่แนะนำ: ใช้แพตช์เป็นทางหลัก และใช้ extracted/ เป็นเอกสารอ้างอิงอย่างเดียว ไม่ต้อง build

เปิดดูว่า prefab ประกอบยังไง แล้วเอาความรู้นั้นไปเขียนโค้ดโคลน/ดัดแปลงตอนเกมรัน ได้ประโยชน์จาก asset โดยไม่ต้องเสี่ยงรื้อของที่ผู้เล่นใช้งานอยู่

08ขั้นตอนทำงาน

แก้เกม

ขั้นทำอะไรหมายเหตุ
1. แก้ซอร์สclient/เขียนคอมเมนต์กำกับทุกจุด ว่าของเดิมทำอะไรและทำไมต้องเปลี่ยน
2. บิลด์dotnet build -c Releaseได้ Assembly-CSharp.dll ประมาณ 27 วินาที
3. ก๊อปทับDurango_Data/Managed/ต้องปิดเกมก่อน ไม่งั้นไฟล์ถูกล็อกเขียนทับไม่ได้

เปิดเกม

ผู้เล่นเปิดผ่าน เล่นเกม.bat ซึ่งเรียก DurangoUpdater.exe ให้เช็กอัปเดตก่อน ตัวเกมจะไม่ยอมเปิดถ้าไม่ได้มาทางนี้ ตอนพัฒนาให้ใส่อาร์กิวเมนต์เปิดตรงได้: 

Durango.exe -durango-updated -force-d3d11 -screen-fullscreen 0

10งานค้าง

เรื่องสถานะติดตรงไหน
เทสปุ่มเข้าเซิร์ฟ รอเทส เขียนเสร็จแล้ว ยังไม่มีใครกดยืนยันว่าเข้าได้จริง
ชื่อเซิร์ฟบน VPS ยังผิดอยู่ ยังขึ้น Multi Play Server ต้อง SSH เข้าไปแก้แล้วรีสตาร์ตเซอร์วิส ยังไม่มีรหัส
ปล่อยอัปเดตให้ผู้เล่น ยังไม่ปล่อย ที่แก้วันนี้ยังอยู่แค่ในเครื่อง รอเทสผ่านก่อนค่อยแพ็กขึ้น release
ย้ายประกาศ + วาป A/B มาเป็นแพตช์ ยังไม่เริ่ม ฝั่งเซิร์ฟพร้อมแล้ว รอทำฝั่งเกม
ใส่ extracted/ ใน .gitignore ยังไม่ทำ 4.1 GB ถ้าเผลอ commit จะกู้ยาก

เอกสารนี้เป็นบันทึกภายในทีม ไม่ใช่คู่มือผู้เล่น ถ้าเจอข้อไหนไม่ตรงกับของจริง ให้ยึดพฤติกรรมของเกมเป็นหลักแล้วแก้เอกสารตาม
