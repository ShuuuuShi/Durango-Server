# ส่วนที่ 1 · ระบบสร้าง — เจอบั๊ก 4 ข้อ (แก้แล้ว 4)

## 🔴 1. สร้างซ้ำใส่ของเดิมได้ไม่จำกัด — **ช่องปั๊ม exp/ความชำนาญ/เควส**

**อาการ:** สร้างกองไฟ 1 อัน แล้วยิง `BuildArtifact` ใส่ **entity เดิม** ซ้ำ ๆ ได้ไม่จำกัด
แต่ละครั้งได้ครบ: exp ก่อสร้าง · ความชำนาญหมวดก่อสร้าง · **ความคืบหน้าเควส "สร้าง N อย่าง"**

**ต้นเหตุ:** `HandleBuildArtifact` ตรวจ 4 อย่าง (มีของจริงไหม · เป็นเจ้าของไหม · งานค้างเกินไหม · สตามินาพอไหม)
แต่ **ไม่เคยตรวจสถานะปัจจุบันของสิ่งปลูกสร้างเลย** — ของที่ `Built` ไปแล้วก็ยังสั่งสร้างซ้ำได้

**ความรุนแรงเพิ่มขึ้นเพราะเพิ่งทำระบบเควส** — เดิมปั๊มได้แค่ exp ตอนนี้ปั๊มเควสได้ด้วย
รวมถึงเควสปลายสาย "ต่อแพ" ที่ตั้งใจให้ทำครั้งเดียว

**แก้:** สร้างได้เฉพาะของที่สถานะเป็น `Occupied` (จองที่ไว้เฉย ๆ) + ธง `_buildingNow`
กันยิงซ้ำระหว่างที่ตัวเดิมยังนับเวลา 2 วิอยู่ (ช่วงนั้นสถานะยังไม่เปลี่ยน)

**เทส:** `--quest-check` รอบ 6.2 — ยิงซ้ำ 5 ครั้ง ต้องโดนปฏิเสธครบ 5 และ exp ต้องไม่ขยับ

## 🔴 2. ขนาดสิ่งปลูกสร้างมาจาก client โดยไม่จำกัด — **จองที่ทั้งย่านได้**

**อาการ:** ยิง `OccupyArtifactSite` พร้อม `Size = 200,200` ⇒ ของชิ้นเดียวจอง **40,000 tile**
คนอื่นสร้างอะไรในย่านนั้นไม่ได้เลย โดยคนทำเสียโควตาตัวเองแค่ 1 จาก 40 ชิ้น

**ต้นเหตุ:**
```csharp
Point2 size = msg.Size;                                  // ← เชื่อ client ตรง ๆ
if ((size.x <= 0 || size.y <= 0) && BlueprintSize.TryGetValue(...))
    size = ...;                                          // ← ใช้ตารางเฉพาะตอน client ส่ง 0 มา
```
เชื่อตารางข้อมูลเกม **เฉพาะตอน client ส่งค่าไม่ถูกต้อง** ซึ่งกลับหัวกลับหาง

**แก้:** `ResolveBlueprintSize()` — **เชื่อตารางข้อมูลเกมก่อนเสมอ**
blueprint ที่ไม่มีในตารางถึงจะใช้ค่าจาก client และตัดไม่เกิน 8×8

---

## 🟠 3. เช็คพื้นที่ทับซ้อนแค่ tile เดียว — **วางบ้านซ้อนกันได้**

**อาการ:** มีของ 1×1 ที่ (10,10) แล้ววางของ 2×2 ที่ (9,10) ⇒ **ผ่าน** ทั้งที่ทับกันอยู่
เพราะของใหม่กิน (9,10)-(10,11) ซึ่งคร่อมของเดิม แต่ **tile มุม (9,10) ว่าง**

**ต้นเหตุ:** `HasArtifactAt(msg.Tile)` เช็คว่า *tile มุมของของใหม่* ตกอยู่ในของเดิมไหม
ไม่ได้เช็คพื้นที่ของของใหม่ทั้งก้อน

**แก้:** `ServerWorld.HasArtifactOverlapping(tile, size)` — เทียบสี่เหลี่ยมต่อสี่เหลี่ยมจริง ๆ

---

## 🟡 4. ทุบสิ่งปลูกสร้างไม่เช็คระยะ

**อาการ:** ยิง `DestructArtifact` ทุบของตัวเองจากอีกมุมเกาะได้ (ตอนจองที่เช็ค `IsWithinReach` อยู่แล้ว
ตอนทุบกลับไม่เช็ค — ไม่สมมาตร)

**ความสำคัญ:** ตอนนี้กระทบแค่ของตัวเอง แต่ระบบมี `ArchitectEntityIds` (สถาปนิกร่วม) อยู่แล้ว
⇒ พอเปิดใช้จะกลายเป็น "ทุบของกองกลางจากที่ไหนก็ได้"

**แก้:** เพิ่ม `IsWithinReach(artifact.Tile)`

## 🔴 5. ที่ยังไม่ได้แก้ — **สร้างไม่กินวัสดุเลย**

`ServerPlayer.Core.cs:498`
```csharp
_conn.Recv<PutMaterialsIntoArtifact>(delegate(PutMaterialsIntoArtifact msg, PacketHeader header)
{
    Send(default(OK), header.Seq);        // ← ตอบ OK เฉย ๆ ไม่แตะกระเป๋าเลย
});
```

⇒ **สร้างอะไรก็ได้โดยไม่ต้องมีวัสดุ** เสียแค่สตามินา 8 หน่วย
บ้าน · กล่อง · กองไฟ · แพ — ฟรีหมด

ข้อมูลเกมมีครบอยู่แล้ว: `blueprints` แต่ละอันมี `slots` บอก tag/จำนวนที่ต้องใช้
เช่น `tutorial_boat` = ท่อนซุง 4 (tag `pillar_*`) + ก้าน 6 (tag `stem`)

**ทำไมยังไม่แก้:** เป็นระบบใหม่ทั้งก้อน (ต้องสกัดตาราง `blueprints` → ตรวจ tag → หักของ → คืนของตอนทุบ)
ไม่ใช่การแก้บั๊ก และไม่อยู่ในขอบเขต "ทำเควสให้เสถียร" — **ควรทำเป็นงานแยก**
มันคือเหตุผลเดียวกับที่ `RecipeRequirements` มีอยู่ฝั่งคราฟต์แล้วแต่ฝั่งก่อสร้างยังไม่มี

> 💡 ตอนนี้เควส "เก็บท่อนซุง 10 อัน" จึงเป็นแค่**ตัวสอน** ไม่ได้บังคับจริง —
> ผู้เล่นข้ามไปต่อแพเลยก็ได้ถ้ารู้ทาง

# ส่วนที่ 3 · เรื่องที่เจอระหว่างทาง — **ชุดเทสไม่เสถียรเพราะ state ค้างในเซิร์ฟ**

ระหว่างตรวจ พบว่าผลเทสแกว่งเองโดยที่โค้ดไม่เปลี่ยน (45 บ้าง 44 บ้าง 39 บ้าง) — ไล่จนเจอ 2 สาเหตุ

## 3.1 บอทเทสใช้ไฟล์เซฟเดิม แล้วสภาพร่างกายสะสมข้ามรอบ

`gp-check` ใช้ id คงที่ `gp-check-1` ⇒ ไฟล์เซฟเดิมทุกรอบ · เจอค้างอยู่ที่:

```
Life: 0.85   ·   Fatigue: 87.5   (FatigueDanger = 85 ⇒ เลือดไม่ฟื้นเอง)
```

⇒ บอทเกิดมาเลือดเกือบหมดและฟื้นไม่ได้ · ตายกลางเทส · ข้อที่ต้องตีสัตว์/แตะซาก/แล่เนื้อ **ตกยกแผงแบบสุ่ม**

**แก้แล้ว:** เพิ่ม `cheat heal` (ฟื้นเต็ม + ล้างความล้า) และให้ `gp-check` เรียกตอนเริ่ม
ต่อจาก `clearbag` ที่มีอยู่แล้วด้วยเหตุผลเดียวกัน · และเรียกอีกครั้งก่อนเข้าช่วงต่อสู้
(สัตว์ที่เสกมาเทสข้อก่อนหน้าสวนกลับจนบอทตายได้)

## 3.2 เทสเลือกเป้าจาก "สัตว์ตัวล่าสุดที่โผล่" ซึ่งไม่ใช่ตัวที่เสก

หลังมีระบบระยะการมองเห็น สัตว์เดินเข้า/ออกจอตลอด ⇒ `AppearAnimal` มาเรื่อย ๆ
"ตัวล่าสุด" จึงมักเป็นตัวที่เพิ่งเดินผ่านมาไกล ๆ ⇒ ยิงธนูแล้วได้ **"เป้าหมายไกลไป (4745 > 1900)"**

**แก้แล้ว:** `cheat spawn` แนบ `[id=...]` มากับข้อความตอบ · เทสใช้ id นั้นตรง ๆ
และ `gp-check` เสกเป้าใหม่ก่อนตีแทนการใช้ตัวที่เลือกไว้ตั้งแต่ต้นเทส
(ของเดิมมักหายไปแล้ว — ถูกฆ่าในข้อก่อนหน้า หรือซากหมดอายุ 150 วิ)

## 3.3 ⚠️ ที่ยังเหลือ — **ต้องรีสตาร์ทเซิร์ฟระหว่างชุดเทส**

`group2-check` ยังแกว่ง (20/20 สลับ 16/20) **แต่พิสูจน์แล้วว่าไม่ใช่เพราะโค้ด**:

| การทดลอง | ผล |
|---|---|
| ปิดระบบระยะมองเห็น (`ViewCulling: false`) แล้วรัน | ยัง 16/20 ⇒ **ไม่ใช่เพราะระบบมองเห็น** |
| **รีสตาร์ทเซิร์ฟใหม่สดแล้วรัน** | **20/20** ⇒ เป็นเพราะ state ค้างในเซิร์ฟ |

ต้นเหตุ: ทุกรอบเทสเสก `cheat spawn` เพิ่มสัตว์เข้าโลกโดยไม่นับโควตาและไม่เก็บกวาด
(เห็นเลขไต่จาก 35 → 45 ตัวใน session เดียว) ⇒ ชุด packet ตอน login โตขึ้นเรื่อย ๆ
แล้วเทสที่ใช้ `Pump(500)` แบบเวลาคงที่เริ่มอ่านไม่ทัน (เช่น ของที่เพิ่งเสกยังไม่เข้ากระเป๋าใน 500 มิลลิวินาที)

**ข้อเสนอ (ยังไม่ได้ทำ — เป็นของสาย character/group2):**
1. ให้ `เทสเกม.bat` **รีสตาร์ทเซิร์ฟก่อนทุกชุดเทส** (ทางที่ง่ายและได้ผลแน่นอนที่สุด)
2. หรือเปลี่ยน `Pump(คงที่)` เป็น "รอจนกว่าจะได้ของที่ต้องการ หรือหมดเวลา"
3. หรือเพิ่ม `cheat despawn` เก็บกวาดสัตว์ที่เสกไว้ตอนจบเทส

> 💡 **เวลาอ่านผลเทสต่อจากนี้:** ถ้าเห็นตัวเลขแกว่งโดยที่ไม่ได้แก้โค้ด
> ให้รีสตาร์ทเซิร์ฟแล้วรันใหม่ก่อนสรุปว่าโค้ดพัง

## 3.4 `multi-check` ฟ้อง "ของถูกปั๊ม" ทั้งที่ไม่ได้ปั๊ม — **เทสวัดผิดตัว**

**อาการ:** `[ตก] ของไม่ถูกปั๊ม — มี 3 หน่วย แต่ได้รวม 4 ชิ้น (multi-1=2 multi-2=1 multi-3=1)`

**ไล่แล้วพบว่าฝั่ง server ถูกต้อง** — `TryReserveGenerator` หักจำนวนใน `lock` ก้อนเดียว
3 หน่วย = จองสำเร็จได้ 3 ครั้งเป๊ะ ไม่ว่าจะรัวพร้อมกันกี่คน

ชิ้นที่ 4 มาจาก **โบนัสสกิลหมวดเก็บของ** ที่ตั้งใจให้มี:

```csharp
Item item  = MakeGatheredItem(generator);
bool bonus = RollGatherBonus();          // สุ่มตามเลเวลหมวดเก็บของ
Item extra = bonus ? MakeGatheredItem(generator) : default;
```

โบนัส **ไม่กินหน่วยของ generator** (ตั้งใจ — เป็นรางวัลของการเลี้ยงสกิล) ⇒
"จำนวนชิ้นที่ได้" มากกว่า "หน่วยที่มี" ได้เป็นปกติ

**แก้ที่เทส:** เปลี่ยนตัววัดจาก *จำนวนชิ้น* เป็น *จำนวนครั้งที่เก็บสำเร็จ*
(นับ `Collected` ที่ `Result == Success` = จำนวนหน่วยที่ถูกจองจริง)
แล้วพิมพ์บรรทัดบอกไว้เวลาโบนัสติด จะได้ไม่ตกใจอีก

```
[ผ่าน] ของไม่ถูกปั๊ม (เก็บสำเร็จไม่เกินหน่วยที่มีจริง)
  (ได้ของรวม 4 ชิ้นจาก 3 หน่วย — โบนัสสกิลติด 1 ครั้ง)
```

**ผลหลังแก้:** 9/9 สามรอบติด (เดิม 8/9 แบบสุ่มตามดวงโบนัส)
