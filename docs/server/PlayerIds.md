# DurangoID — ระบบสมัครไอดีของผู้เล่น (4 ก.ย. 2026)

เจ้าของสั่ง: *"ออกแบบระบบสมัครไอดีใหม่เลย ใช้เลขสุ่มจากเราเป็นไอดี และมีหน้าให้สมัครไอดีด้วย"*
และเลือกแนวทาง **ผูกผ่านหน้าเว็บด้วย IP** + **บังคับสมัครทุกคน**

---

## ทำไมต้องมี

ตัวตนของผู้เล่นเดิมผูกกับ **IP อย่างเดียว** (`AccountStore`) ซึ่งพังกับมือถือ

| ค่าที่ใช้ระบุตัวตน | PC | Android |
|---|---|---|
| `account_id` (NPSN) | GUID เก็บใน PlayerPrefs (`Platform_PC` override) | **ค่าว่าง** — `Platform_Android` ไม่ override |
| `adid` | ว่าง | **ว่าง** — ไม่ override เช่นกัน |
| เหลืออะไรให้เซิร์ฟใช้ | account_id + IP | **IP อย่างเดียว** |

เน็ตมือถือ/CGNAT สลับ IP เมื่อไหร่ ตัวละครหายทันที และเราแก้โค้ดใน APK ไม่ได้ (IL2CPP)

## หลักการ

ผู้เล่นเปิดหน้า `/id` **จากเครื่องที่จะเล่น** → สมัครได้เลข 8 หลักที่เซิร์ฟสุ่มให้ + ตั้ง PIN →
กด "ผูกเครื่องนี้" → เซิร์ฟจด IP ปัจจุบันไว้ให้ไอดีนั้น (ค่าเริ่มต้น 30 วัน)
พอเข้าเกม เซิร์ฟเทียบ IP แล้วรู้ว่าเป็นไอดีไหน จึงคืนตัวละครได้ถูกคน

- **ตัวละครผูกกับไอดี ไม่ใช่ IP** — IP เป็นแค่ "สะพาน" ที่บอกว่าเครื่องไหนกำลังขอ
- **หลายไอดีผูก IP เดียวกันได้** (บ้านเดียวกัน/CGNAT) — `/accounts` คืนตัวละครของทุกไอดีที่ผูก IP นั้น
  แล้วให้หน้าเลือกตัวละครของตัวเกมเป็นคนแยกเอง ไม่ต้องแย่ง binding กัน
- **สร้างตัวละครใหม่** ผูกเข้ากับไอดีที่กด "ผูกเครื่องนี้" ล่าสุดจาก IP นั้น
- IP เปลี่ยน = กลับมาที่หน้าเว็บ เข้าสู่ระบบ กด "ผูกเครื่องนี้" อีกครั้ง (บุ๊กมาร์กไว้ กด 2 ครั้งจบ)

## Endpoint

| method | path | ใช้ทำอะไร |
|---|---|---|
| GET | `/id` | หน้าเว็บสมัคร |
| GET | `/id/status` | IP นี้ผูกไอดีอะไรไว้ · บังคับสมัครไหม · มีตัวละครเก่าให้รับกี่ตัว |
| POST | `/id/register` | `pin`, `name` → สุ่มเลขไอดีให้ แล้วผูกเครื่องที่สมัครทันที |
| POST | `/id/login` | `id`, `pin` → ข้อมูลไอดี + รายชื่อตัวละคร |
| POST | `/id/bind` | `id`, `pin` → ผูก/ต่ออายุ IP ปัจจุบัน |
| POST | `/id/unbind` | `id`, `pin` → เลิกผูก IP ปัจจุบัน |
| POST | `/id/adopt` | `id`, `pin` → รับตัวละครเก่าที่เคยจองจาก IP นี้และยังไม่มีไอดีเป็นเจ้าของ |
| POST | `/id/change_pin` | `id`, `pin`, `new_pin` |

ทุก endpoint ที่แตะข้อมูลของไอดีต้องผ่านไอดี+PIN เสมอ ไม่เชื่อ IP อย่างเดียว
กันไล่เดา PIN ด้วยการนับครั้งที่ผิดต่อ IP (10 ครั้งใน 15 นาที)

## ตั้งค่า (`data/config.json` → `PlayerIds`)

```json
"PlayerIds": {
  "Enabled": true,
  "Required": true,
  "BindingDays": 30,
  "PublicUrl": ""
}
```

- `Required: true` = ไม่มีไอดีที่ผูก IP นี้ **สร้างตัวละครไม่ได้ และหน้าเลือกตัวละครจะว่าง**
- ⚠️ **เปิดบนเซิร์ฟที่มีคนเล่นอยู่แล้ว = ทุกคนต้องไปสมัคร + กด "รับตัวละครเดิม" ก่อนถึงจะเล่นต่อได้**
  ควรประกาศล่วงหน้าและมีลิงก์หน้าสมัครพร้อม
- config ไฟล์เก่าที่ยังไม่มีคีย์นี้จะได้ค่าเริ่มต้นทั้งก้อน (`Required: true`) เพราะทั้งเซกชันเป็น null

## ⚠️ ข้อจำกัดที่ยังเหลือ — มือถือยังไม่จบด้วยระบบนี้ระบบเดียว

ระบบไอดีแก้เรื่อง **"เซิร์ฟรู้ว่าใครเป็นใคร"** ได้แล้ว แต่บนมือถือยังมีอีกด่าน:

`Server.ConnectTo(ip)` (เส้นที่ client มือถือใช้ตอนต่อเซิร์ฟที่ไม่ใช่ของ Nexon) ตั้ง
`cluster.OnRequestAccount` เป็นโค้ดที่คืน `_localPlayer` **ตัวเดียวจากหน่วยความจำ** และตั้ง
`cluster.Mode = Mode.Offline` ⇒ หน้าเลือกตัวละคร **ไม่เคยยิง `POST /accounts`** เลย
(ตอนสร้างตัวละครยิงมาที่เซิร์ฟจริง แต่ตอนขอรายชื่อไม่ยิง — ตรงกับอาการที่เจอเป๊ะ)

ทางออกที่มีอยู่แล้วในตัวเกม: cluster ที่ key เป็น `"online"` ตั้ง `OnRequestAccount = null`
⇒ ยิง `POST /accounts` จริง และ `GatewayUrlRoot` ของมันคือ `"http://127.0.0.1:" + 8190`
ซึ่ง**เป็น literal ตัวเดียวกับที่เราแพตช์อยู่แล้ว** (ดู `docs/server/Android.md`)

**สิ่งที่ต้องทำต่อ:** ทดสอบบนอีมูเลเตอร์/เครื่องจริงว่าเมนูมือถือมีรายการเซิร์ฟ `"online"` ให้เลือกอยู่แล้วไหม
ถ้ามี ผู้เล่นแค่เลือกอันนั้นแทน "Creative Island" ตัวละครก็จะเซฟติดทันที

## เปิดใช้จริงบน VPS แล้ว (5 ก.ย. 2026)

`187.53.129.69` — เปิด `Enabled: true, Required: true` ครบทั้ง 5 เกาะ **ไม่ได้ restart** (config hot-reload 5 วิ)
หน้าสมัคร: `http://187.53.129.69:8190/id`

⚠️ **กับดักที่เจอตอนเปิด: โหมดหลายเกาะไม่ได้อ่าน `data/config.json`**
`Program.cs:297` ชี้ config ไปที่ `data/islands/<island>/config.json` เมื่อรันด้วย `--island`
⇒ แก้ `data/config.json` ไม่มีผลอะไรเลย ต้องแก้ไฟล์ของทุกเกาะ:

```bash
python3 - <<'PY'
import json,glob
for f in sorted(glob.glob('/opt/durango/data/islands/*/config.json')):
    d=json.load(open(f,encoding='utf-8'))
    d['PlayerIds']={'Enabled':True,'Required':True,'BindingDays':30,
                    'PublicUrl':'http://187.53.129.69:8190/id'}
    json.dump(d,open(f,'w',encoding='utf-8'),ensure_ascii=False,indent=2)
PY
chown -R durango:durango /opt/durango/data/islands
```

⚠️ **`web/id.html` ไม่ได้ไปกับ publish** — ต้อง scp แยก ไปไว้ที่ `/opt/durango/web/id.html`
(`WorkingDirectory` ของทุก service = `/opt/durango` ⇒ ตรงกับตัวเลือกแรก `cwd/web/id.html`)
ไม่มีไฟล์นี้ = `/id` ตอบ 404 ทั้งที่ `/id/status` ทำงานปกติ (เข้าใจผิดง่ายว่าระบบไม่มีในบิลด์)
